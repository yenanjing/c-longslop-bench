阿里 Qwen 团队最近提出了 Trace2Skill，思路说起来并不复杂：让 Agent 像人类专家那样，先把大量执行经验吃透，再把这些经验浓缩成一份通用的、能跨模型迁移的技能文档。整个过程不需要更新模型参数，也不需要外挂检索，一个 35B 的开源模型就足够跑起来。

**技能扩展的瓶颈**

给 LLM Agent 配上领域专属的 Skill，如今已经是处理复杂任务的主流做法。所谓技能，本质上是一份结构化、可复用的文档，把任务流程、领域知识和操作要点都写清楚。Anthropic 那套 skill 框架就是典型——技能被定义成轻量级的、由专家撰写的文档，支持动态加载和渐进式披露。

麻烦出在“专家撰写”这四个字上。Agent 被部署到越来越多细分场景，对专业技能的需求是指数级上涨的，靠人写、靠人维护根本跟不上。更尴尬的是，就算是专家认真写出来的技能，也未必对具体某个 Agent 有用。论文里有个很说明问题的例子：一份能让 122B Agent 在 SpreadsheetBench 上提升 20 个百分点的专家技能，换到 35B Agent 上，成绩反而掉了。

那让 LLM 自己写技能行不行？也不太行。只靠模型参数里的知识生成的技能，提升非常有限——参数化知识缺的恰恰是目标领域的具体细节和常见坑。哪怕是顶级闭源模型，写出来的技能也很难带来实质变化。

在线学习看起来有希望，但有两个绕不开的问题。一是现有方法往往针对每条轨迹的局部教训新建一个很窄的技能，结果技能库越来越臃肿，检索也越来越难；而人类专家的做法是，在一个领域里精心打磨一份综合性文档。二是在线范式下，技能是随着单条轨迹一条条顺序更新的，相当于作者还没把一个领域摸透就急着改文档。正确的顺序明明应该是先建立全局的高层理解，再把它固化成技能。

（图注：左边是现有在线范式——轨迹教训顺序演进技能库；右边是 Trace2Skill——并行分析一整池轨迹，分层整合教训，诱导出可泛化的 SOP。）

**Trace2Skill：按人类专家的方式写技能**

阿里 Qwen 大模型应用团队提出的 Trace2Skill，正是冲着上面这些问题来的。核心思想一句话就能说完：像专家一样写技能——先全面分析广泛的执行经验，再蒸馏成单一、综合的指南。

（图注：Trace2Skill 三阶段流水线。Stage 1：冻结参数的 Agent 在演化集上跑任务，产出成功和失败轨迹。Stage 2：并行的错误分析器和成功分析器各自独立处理轨迹、提出技能补丁。Stage 3：用归纳推理加程序化冲突检测，把所有补丁合并成一次更新。）

整套流水线分三个阶段，分工明确，工程上也做得很扎实。

先说技能怎么定义。在 Trace2Skill 里，一份技能是一个结构化的、人能读的知识目录：一个根 Markdown 文档（也就是 SKILL.md），外加一组辅助资源。SKILL.md 用自然语言写程序性知识——什么时候用某项技术、分步策略、已知的失败模式；辅助资源则提供可执行脚本（处理确定性子任务）和领域参考资料。

演化的目标也很直接：不动模型参数，只从演化集的执行轨迹里构建出一份更好的技能。论文考察了两种初始化方式，一是技能深化，从人类专家写的技能出发；二是技能创建，从 LLM 靠参数化知识生成的草稿出发。

Stage 1，轨迹生成。Agent 框架用的是 ReAct。给定初始技能，Agent 在演化集的每个任务上跑一遍，得到一条完整轨迹：推理链、工具调用、观测结果，再加一个任务是否成功的标记。所有轨迹按成功、失败分成两堆。

这一步完全可以并行。实际操作里，用 122B 模型生成 200 条 50 步以上的轨迹，不到 2 个 GPU 小时就跑完了。

Stage 2，并行多智能体提补丁，这是整篇论文最有意思的部分。作者设计了两类专门的分析子 Agent，每条轨迹交给一个独立的子 Agent 处理。

成功分析器是单次调用：清洗轨迹、找出促成正确答案的可泛化行为模式、提出补丁。成功轨迹不需要交互式诊断，单次调用够用也高效。

错误分析器就不一样了，它跑的是 ReAct 风格的多轮循环：可以翻完整条轨迹、读取输入输出文件、把 Agent 的答案和标准答案对照，一步步把根因范围缩小，直到提出一个有因果依据的补丁。要是诊断不出来，这条轨迹直接从补丁池里踢出去。这个质量门控很关键，它保证每个补丁都对应一个已经验证过的失败原因。

还有一个关键设计：所有分析器都基于同一份冻结副本运行，彼此看不见对方提的补丁。这种独立性避免了过早收敛，把每条轨迹观察的多样性完整保留了下来。

Stage 3，无冲突地整合补丁。Stage 2 产出的补丁池里是所有成功和错误分析器的提案，Stage 3 要把它们捏成一次连贯的技能更新，同时做到两件事：消除冲突、归纳泛化。

（图注：分层合并与程序化冲突预防。补丁按层的层次结构合并，每层里最多若干个补丁合成一个整合补丁；合并算子负责去重、解决冲突、保留独特见解。整条流水线是自包含的——同一个 LLM 既收集经验、分析经验，又把它蒸馏成改进后的技能，不需要外部老师。）

有三条确定性护栏兜底：引用了不存在文件的补丁直接拒绝；同一文件里目标行范围重叠的编辑标记为冲突、搁置；更新后的技能必须通过格式校验器。

分层合并不只是为了消冲突，它本质上是在补丁池上做归纳推理。每个补丁都来自单条轨迹，整个补丁池其实编码了 Agent 在演化集上的行为分布。合并算子被明确要求找出“流行模式”，也就是在多个独立补丁里反复出现的编辑。道理也好理解：跨多样轨迹反复出现的观察，更可能反映系统性的任务属性，因此更容易泛化到没见过的任务和其他 Agent 模型；相反，只在一两条补丁里冒出来的编辑，就当成潜在特例丢掉。

这种按流行度加权的整合，正是“深度逐轨迹分析能产出可泛化技能”的核心原理。

顺带说一下两种演化模式。技能深化，初始技能是人类专家写的，流水线从失败轨迹里提取针对性的失败指导、从成功轨迹里强化有效策略，把它磨得更细。从零创建技能，初始技能只是 LLM 凭参数化知识写的草稿——实验表明这种草稿几乎不带来任何实质提升，和无技能基线差不多——所以从这儿起步的演化才算真正的技能创建：完全靠轨迹证据，从一个性能中性的起点造出有用的技能。

**实验结果**

主实验放在电子表格操作上。论文在 SpreadsheetBench-Verified 上跑，400 个样本切成 200 个演化集、200 个测试集，另外还在 WikiTableQuestions（WikiTQ）上测分布外泛化。用的是两个 Qwen3.5 MoE 模型：Qwen3.5-122B-A10B 和 Qwen3.5-35B-A3B。Stage 2 部署 128 个子 Agent 并行，合并批量大小为 32。

第一个发现：人类写的技能是强先验，但不好移植。人类基线技能对 122B Agent 效果很好（SpreadsheetBench-Vrf 48.33%，WikiTQ 74.68%），放到 35B Agent 上却成了负担（SpreadsheetBench-Vrf 只有 9.67%，还低于无技能的 19.00%）。参数化基线则始终贴着无技能水平走。

第二个发现：技能深化能稳稳增强人类技能。122B 驱动的 Deepening+Error 在 SpreadsheetBench-Vrf 上提升 17.5 个百分点，+Combined 提升 21.5 个百分点。而且这些增益不只属于生成它的那个模型——35B 驱动产出的技能给 122B 用，照样提升 16.7 个百分点。

第三个发现：从零创建的技能，质量能追平甚至超过人类手写。35B 驱动的 Creation+Error 技能交给 122B Agent 用，在 WikiTQ 上提升 57.65 个百分点（达到 81.38%），比人类基线还高 6.7 个百分点。

这个结果挺让人意外——35B 模型写出来的技能，竟然能让 122B 模型在分布外任务上大幅超过专家手写技能。

第四个发现：+Combined 最稳，+Error 最可靠，+Success 波动最大。+Combined 在四种 Author-Mode 组合里都保持高水平；+Error 每个设定下都是正值，是最安全的默认选项；+Success 虽然能打出最大的单项提升，但也可能跌破基线。

**数学推理**

为验证这套方法是不是只适用于表格，论文转到数学推理上：用 DAPO-Math-Train-400 做演化集，在 DAPO-Math-Test-100（分布内）和 AIME 2026（分布外竞赛数学）上评估。结果相当一致：

122B 驱动 → 同模型：DAPO +3.0 pp，AIME +2.9 pp
122B 驱动 → 迁移 35B：DAPO +5.0 pp，AIME +5.0 pp
35B 驱动 → 同模型：DAPO +4.0 pp
35B 驱动 → 迁移 122B：DAPO +2.0 pp

这确认了基于轨迹的蒸馏跟领域无关，扩展到竞赛级评估也成立。

**视觉问答**

论文还在 DocVQA 上测了多模态视觉推理，这里有个挺有意思的反转：35B Agent 无技能时的原始表现（0.6843 ANLS）反而比 122B（0.6424 ANLS）好；可一旦当技能作者，35B 就明显落后——它驱动的技能给 122B 几乎没提升（只有 +0.009 ANLS），用在自己身上还掉了 0.062 ANLS。

反过来，122B 驱动的技能就很能打：同模型提升 0.1639 ANLS、15.3 个百分点准确率，迁移到 35B 同样强劲（+0.1554 ANLS，+13.6 个百分点准确率）。

结论是：用归纳推理写技能——从轨迹里识别反复出现的失败模式、蒸馏成可操作的规则——和“把任务做好”是两种不一样的能力。DocVQA 上跑得好的模型，未必擅长反思“我为什么会失败”，也未必能把观察泛化成可迁移的技能。

**深入拆解**

并行整合 vs 顺序编辑。论文对比了并行整合和在线顺序编辑，设了两个顺序基线：Seq-B=1（每条轨迹更新一次技能）和 Seq-B=4（每 4 条轨迹更新一次）。在 122B 上，并行整合全面领先：Vrf 比 Seq-B=1 高 4.0 pp，比 Seq-B=4 高 6.8 pp。

效率差距更夸张：并行大概 3 分钟，Seq-B=1 要 60 分钟（20 倍），Seq-B=4 要 15 分钟（5 倍），而且差距随轨迹数量线性拉大。

并行整合还有个结构性优势：所有补丁提案都源自同一份冻结的初始技能，避免了在线设定里固有的顺序漂移——技能每更新一次，后面轨迹被分析时的上下文就跟着变了。分层合并则是在全部轨迹局部观察的整体上同时做归纳，挑的是在多样轨迹里反复出现的模式，而不是在最近几次更新里反复出现的模式。

技能蒸馏 vs 检索记忆。论文拿 Trace2Skill 和 ReasoningBank 做了对比。后者从每条轨迹里存一条可泛化的教训，推理时按任务相似度检索记忆。对比用的是同一个轨迹池，区别在于把它蒸馏成可移植的技能文档（也就是 +Combined）。差距很明显：122B 上，+Combined 全面超过 ReasoningBank——Vrf +13.8 pp、Soft +7.1 pp、Hard +8.2 pp；35B 上 ReasoningBank 几乎失效（20.50% Vrf，和无技能的 19.00% 基本一样）。

论文把差距归到三点：检索质量对表面相似度敏感，测试分布一变就退化，而蒸馏出来的技能无需改动就能迁移；检索到的片段要和任务上下文抢注意力，技能却是在系统提示里预加载、早就整合好的；层次合并会主动去重和抽象，检索银行里的原始轨迹摘要则没经过冗余过滤。

Agent 式错误分析 vs 单次 LLM 调用。不少先前工作是用一次非交互的 LLM 调用从错误轨迹里推教训。论文把 Agent 式错误分析（+Error）和单次调用基线（+Error LLM）做了全面对比。Agent 式分析在四种 Author-Mode 组合的加权 Avg 上全赢：122B Deepening +12.2 pp、122B Creation +0.8 pp、35B Deepening +3.2 pp、35B Creation +13.3 pp。

对 33 个共享错误案例的定性研究说明了原因：两条流水线只有 12.1% 的案例达成强一致，54.5% 的案例存在明显分歧。LLM-only 分析器在 57% 出现解析错误消息的案例里过度归因于解析失败（Agent 式只有 14%），甚至给一条输出本来就正确的轨迹硬编了三个失败原因。Agent 式分析器能访问工件、能验证修复，所以能拒绝误报，把每个补丁都锚定在已经验证过的失败机制上。

**泛化的标准操作程序**

论文还对 122B Deepening+Combined 产出的 323 个补丁做了定性分析，提炼出四条核心 SoP：

SoP 1，公式重算与写回验证（178/323）：每次写入公式后跑 recalc.py，再用 data_only=True 重新打开确认；跳过这步是最常见的错误模式。

SoP 2，工具选择上 openpyxl 优于 pandas.to_excel()（177/323）：pandas 负责读取和转换，openpyxl 负责写回。pandas.to_excel() 会悄悄破坏公式关系和命名范围。

SoP 3，显式读回验证（138/323）：写入后重新打开输出文件，确认每个目标单元格持有期望值再提交。

SoP 4，结构编辑安全性（53/323）：按降序删除行，防止索引偏移；编辑前复制输入工作簿，保住格式和公式。

低频观察被分流到 13 个补充参考文件里。这和成熟的技能设计实践是一致的：主文档写通用规则，references/ 目录按需查询低频边缘情况。Trace2Skill 从轨迹证据里自动把这套层次结构还原了出来。

**和现有方法的关系**

Trace2Skill 和几个研究方向都有交集，但差异点有三个：一是同时合并所有轨迹的局部补丁，而不是一条条顺序编辑，避开了顺序依赖和过拟合；二是目标是统一的 Anthropic 风格技能目录，不是窄 API 对象或双存储；三是进化出来的技能直接被消费，天然兼容任何 Agent 框架。整条流水线用 35B 开源模型就能驱动。

**总结与展望**

Trace2Skill 证明了一件有点反直觉的事：经验可以被蒸馏成可迁移的声明式技能。这挑战了“经验本质上是模型特定、任务特定的”这个常见假设。

核心发现连起来看是这样的：复杂的 Agent 经验可以被打包成高度可迁移的声明式技能——不用更新参数，也不用外部检索；35B 驱动的技能能显著提升 122B，还能泛化到分布外任务；并行整合在效率和性能上都碾压顺序在线更新；一份紧凑的技能文档比检索式情节记忆更充分地利用了轨迹证据；层次目录结构（SKILL.md + references/）自动编码了可泛化模式和细粒度陷阱。

当然，作为一篇还在进行中的工作，论文也坦白了当前的局限：(1) 很难量化单个编辑补丁的因果贡献；(2) 还没做到追踪 Agent 推理时对技能目录具体部分的依赖程度。团队计划在未来工作里引入更细粒度的归因追踪机制。
