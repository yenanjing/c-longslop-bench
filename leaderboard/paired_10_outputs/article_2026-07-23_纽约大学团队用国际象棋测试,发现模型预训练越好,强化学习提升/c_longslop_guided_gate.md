纽约大学团队用国际象棋搭了一套可控试验台，完整跑通了「预训练→监督微调→可验证奖励上的强化学习」这一整套，他们发现啊，说的是在给定强化学习算力的时候，预训练验证损失就能很好地预测最终表现了；也就是说，预训练数据越多，强化学习曲线爬得越陡。

Understanding Reasoning from Pretraining to Post-Training，Github 链接就放在这儿了。

模型与数据这块儿，说的是 huggingface.co/pavelslab-nyu/pre2post-chess，两个团队总算力一样，一个把九成预算砸进强化学习，另一个只留一半给 RL，另一半继续预训练，谁的最终解题率更高，事先并不直观。也就是说，这篇论文用国际象棋搭了 36 组实验来回答这个问题了。

现实里啊，谈大模型推理的时候，很多人默认把算力砸进后训练，也就是用对错可自动判定的奖励去做强化学习，也叫 reinforcement learning，简称 RL。另一边，预训练还在继续加数据、加参数。两边各有一套规模定律，中间却缺一张量化对照，说的是预训练选得好不好，会怎样改变后面每一分 RL 算力的回报；还有 RL 又到底在改策略的哪一块了。

在真实大模型上回答这两个问题很难啊。预训练语料又大又杂，行为很难归因；再把预训练和 RL 两边一起做算力扫描，成本几乎不可承受。纽约大学主导的这项工作换了一条路，说的是把国际象棋当成可控试验台，完整复刻今天常见的大模型训练流程，在 5M 到 1B 参数上把预训练和 RL 怎么互相影响给量化清楚了。

为什么用棋盘做试验台呢。棋很适合拿来做严谨对照实验。动作空间小、对错可核验，说的是每一步着法都能对照引擎或标准答案判定，推理轨迹里的每一步也透明，自然语言通常只剩最终答案对不对。人类对局数据量大，还能按需筛子集，也就是说，作者从 Lichess 收集约 54B token 的 Blitz/Rapid 对局，并可按 Elo、对局长度做子采样。小模型就已经有可测的棋力变化，换参数规模、换预训练 token、换 RL 步数，下游都能看出差别，算力扫描才做得出。

论文的目标很明确，说的是隔离「预训练规模」和「可验证 RL 」怎么互相作用，并不追求最强下棋模型了。

上面那套只用棋步 token 的思考练好之后，接着就进入强化学习了，说的是从 SFT 策略出发，在谜题环境用二元结果奖励，也就是整条正确解法，一步接一步全部走对才得 1，否则 0；优化器用 GRPO，这是一种相对组内基线估计优势的策略优化方法。评估用 1480 道战术谜题，作者按难度分成 B1 到 B5 五档，B1 最易，B5 最难；主文汇总指标多看 B1 到 B4，最难的 B5 留给机制分析了。

对照实验还说明了一个事儿，说的是只 SFT 目标着法，pass@1 会涨，但 pass@8/16 几乎不动；加上合成推理轨迹后，各 pass@k 一起改善了。后续 RL 都从这个设定起步了。

算力怎么分呢，说的是前沿上 RL 占比会升高。固定总 FLOPs 和模型大小的时候，预训练多吃一点 token，初始化更强，但留给 RL 的算力更少。作者在 20M、50M、200M、680M 上扫多档预训练检查点，各自做完同一套 SFT，再跑 1000 到 5000 步 RL，画出固定预算下的帕累托前沿，也就是同样这么多算力能拿到的最好成绩连成的那条线；落在线之外的配方，都是算力没花在更值的地方了。

上面说有三点很清楚，咱们一条一条来看，先说 RL 几乎总在抬高 pass@1，而且训练越久越高。预算小的时候，前沿更爱选「预训练更多、RL 更少」的点，说明早期 RL 严重受初始化拖累，预训练基础差的模型多堆 RL，也补不回预训练不足了。预算变大后，前沿上的 RL 占比抬升。例如 20M 模型上，RL 占比从约 5% 走到约 32%。

说完 pass@1 ，咱们再看 pass@16 ，也就是采样 16 次里至少对一次，这个指标就混杂得多了。小模型上 RL 前期还能拉一把；更大模型上嘛，曲线接近平坦，有时还略降。这时候再加预训练，往往比把同样算力继续扔给 RL 更划算。这么看，这跟「 RL 主要抬 pass@1 、对大 k 覆盖帮助有限」的已有观察就对上了，后文机制节会解释原因，这里先按下不表。

结果按难度呈现出两种不同规律。简单谜题上， RL 主要放大 SFT 已经倾向的正确着法。困难谜题上，它既能把几乎从未被偏好的正确着法从尾部捞上来，也会把错误着法越训越自信。拿一张难例来说，就更直观了。

接上面那张难例，具体看难例 B5 ，正解是 b6e3 。预训练几乎全押在错着 d6e5 上； SFT 后概率摊开了，但正解还是低； RL 过程中正解升到了首位，这就是尾部发现，同时另一错着 b6b4 也保有不少概率权重，这就是错误放大了。

这直接解释了 Figure 2 里 pass@1 与 pass@16 的分叉：概率在往「当前更可能对的一条」集中，覆盖面不一定变宽；难题上还在强化错误下法。若希望大 k 也持续变好，需要压错误放大、扩大正确解的支撑集，单靠把现有策略削尖不够。

再看推理轨迹结构上啊， RL 更像是在加宽搜索，也在提高候选着法质量，最大深度其实变化不大；这里要注意，模型还是很难在大约 5 步之后，把正确的后续走法找回来。那作者据此建议的是，未来合成 SFT 数据可以更有意识地鼓励更深、更系统的搜索，别只是堆宽度了。

棋盘上的规律，数学文本里也能看见。这套结论未必只是棋盘巧合。为了检查，作者用 1B 的 OLMo-2 ，在约 200B token 的数学向混合语料上预训练（约 70% Nemotron-CC-Math ， 30% Dolma3 ），沿途取出 10B–200B 的 14 个检查点；再经 NuminaMath-CoT 上一轮 SFT ，然后在 GSM8K 、 MATH 、 DeepScaler 混合题上做 RL ，用 pass@1 评估。

近似线性变陡，形态与棋盘结果同向。

而且你看，哪怕任务格式、数据分布、训练配方都不同，同一种预测结构还是出现了，也就是预训练更久的检查点，在固定 RL 算力下终点更高， RL 曲线也更陡。这里得说清楚，这只是定性迁移证据，但是它说明「预训练性质 → RL 曲线」这个接口，未必就是棋盘上的特例了。

边界与判断。这套结论有明确适用边。棋的动作可核验、数据可筛选，归因干净；外推到开放文本时，奖励噪声和动作歧义都会更大。斜率律只在基准未饱和的局部成立；简单题见顶后，不能再用同一斜率讲故事。算力用 FLOPs 做分配单位，有利于比算法账，但实际运行时间（墙钟时间）还会吃系统开销，安排训练计划时不能把两者混为一谈。

即便如此啊，面对「还要不要继续靠大量人类数据打底、以及经验反馈能不能替代先验」这类争论，这篇给出的是一张可计算的账，说的是 RL 得有足够强的预训练初始化，才会真正有效；预算变大以后，最优配方里 RL 的份额应该往上升；同时呢， RL 会放大正确模式，也会在难题上继续加固错误模式。你要是对照当下不少团队「预训练随便糊、 RL 硬堆步数」的打法，这更像是一组反例，也就是底子不够的时候， GRPO 再多跑几千步也补不齐。那更值得试的，或许就是交错安排预训练与 RL ，再加一个专门对付错误模式放大的后训练目标了。
