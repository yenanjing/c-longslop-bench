纽约大学团队用国际象棋搭了一套可控试验台，完整跑通「预训练→监督微调→可验证奖励上的强化学习」，至于发现，其实就是给定强化学习算力时，预训练验证损失就能很好预测最终表现，而且预训练数据越多，强化学习曲线爬得越陡。

回过头想，模型与数据其实在于， huggingface.co/pavelslab-nyu/pre2post-chess两个团队总算力一样，一个把九成预算砸进强化学习，另一个只留一半给 RL 、另一半继续预训练，谁的最终解题率更高，事先并不直观。这篇论文用国际象棋搭了 36 组实验来回答。

从这个角度看，现实里，谈大模型推理时很多人默认把算力砸进后训练，也就是用对错可自动判定的奖励做强化学习（ reinforcement learning ， RL ）。另一边，预训练还在继续加数据、加参数。两边各有一套规模定律，至于中间却缺一张量化对照，其实就是预训练选得好不好，会怎样改变后面每一分 RL 算力的回报，而且 RL 又到底在改策略的哪一块。

大家知道，在真实大模型上回答这两个问题很难了。但是我觉得，预训练语料又大又杂，行为很难归因，而且再把预训练和 RL 两边一起做算力扫描，成本几乎不可承受。纽约大学主导的这项工作换了一条路，也就是把国际象棋当成可控试验台，完整复刻今天常见的大模型训练流程，在 5M 到 1B 参数上把预训练和 RL 怎么互相影响量化清楚。

为什么用棋盘做试验台棋很适合拿来做严谨对照实验。动作空间小、对错可核验，也就是每一步着法都能对照引擎或标准答案判定，推理轨迹里的每一步也透明，自然语言通常只剩最终答案对不对。人类对局数据量大，至于还能按需筛子集，其实就是作者从 Lichess 收集约 54B token 的 Blitz/Rapid 对局，同时直接可按 Elo 、对局长度做子采样。小模型就已经有可测的棋力变化，也就是换参数规模、换预训练 token 、换 RL 步数，下游都能看出差别，算力扫描才做得出。

说到底，论文的目标很明确其实在于，隔离「预训练规模」和「可验证 RL 」怎么互相作用，同时直接不追求最强下棋模型。

表面上看，流程分三段，刻意模仿现在大模型训练的常见习惯，也就是预训练，也就是把棋局编成棋子、起点、终点、特殊标记四元组 token ，词表只有 81 ，而且模型学人类对局的下一步预测。

换句话讲，监督微调（ SFT ）其实在于，在谜题上训练。预训练模型只见过着法序列，没有显式推理。作者不借助外部搜索工具，改让模型自己写「思考」，也就是从预训练策略采样多条候选后续走法，按公共前缀合成树，再深度优先序列化成<T>…</T>推理轨迹，最后提交正解着法。思考内容仍是棋步 token ，不用自然语言。

真正关键的地方在于，强化学习其实在于，从 SFT 策略出发，在谜题环境用二元结果奖励，也就是整条正确解法（一步接一步）全部走对才得 1 ，否则 0 ，而且优化器用 GRPO （一种相对组内基线估计优势的策略优化方法）。评估用 1480 道战术谜题，作者按难度分成 B1–B5 五档（ B1 最易， B5 最难），而且主文汇总指标多看 B1–B4 ，最难的 B5 留给机制分析。

其实看对照实验还说明其实在于，只 SFT 目标着法， pass@1 会涨，但 pass@8/16 几乎不动，而且加上合成推理轨迹后，各 pass@k 一起改善。后续 RL 都从这个设定起步。

为什么说算力怎么分其实在于，前沿上 RL 占比会升高固定总 FLOPs 和模型大小时，预训练多吃一点 token ，初始化更强，但留给 RL 的算力更少。作者在 20M 、 50M 、 200M 、 680M 上扫多档预训练检查点，各自做完同一套 SFT ，再跑 1000–5000 步 RL ，画出固定预算下的帕累托前沿，也就是同样这么多算力能拿到的最好成绩连成的那条线，而且落在线之外的配方，都是算力没花在更值的地方。

看 pass@1 （一次采样就算对），有三点很清楚。

从这个角度看，RL 几乎总在抬高 pass@1 ，而且训练越久越高。预算小的时候，前沿更爱选「预训练更多、 RL 更少」的点，说明早期 RL 严重受初始化拖累，预训练基础差的模型多堆 RL ，也补不回预训练不足。预算变大后，前沿上的 RL 占比抬升。例如 20M 模型上， RL 占比从约 5% 走到约 32%。

大家知道，pass@16 （采样 16 次里至少对一次）则混杂得多了。其实换个角度看，小模型上 RL 前期还能拉一把，而且更大模型上曲线接近平坦，有时还略降。这时再加预训练，往往比把同样算力继续扔给 RL 更划算。这和「 RL 主要抬 pass@1 、对大 k 覆盖帮助有限」的已有观察一致，后文机制节会解释原因。

有意思的是，联合 scaling 其实在于，预训练 loss 预测后 RL 表现前沿行为引出第二个问题，也就是预训练侧的性质，能否预测一段 RL 曲线会长成什么样。

换句话讲，是参考算力点上的表现，是「 RL 算力每增加一个数量级，奖励涨多少」的局部斜率了。其实换个角度看，也就是说，也就是在拟合区间里， RL 算力每乘 10 ， pass@1 大约固定加。

真正关键的地方在于，预训练损失大致定了后 RL 能爬到多高，预训练数据量大致定了这条曲线爬多快，分开来看。

其实看水平由预训练损失决定。 在中等难度 B3–B4 上，预训练验证损失越低，同一 RL 算力下的后 RL pass@1 越高，而且参考算力从 ＄10^{16}提到＄时，两者的排序一致性（越接近 $-1$，说明「损失越低、表现越好」越稳）从约 $-0.93$ 紧到约 $-0.99$。高 RL 算力下的后 RL 表现，比「刚做完 SFT 、还没 RL 」的起点更贴预训练损失，也就是预训练的影响会在 RL 过程中被放大。

为什么说斜率主要由预训练数据量决定。与正相关（ Pearson）。联合拟合说白了，也就是数据每多一个量级， RL 的爬坡曲线就明显陡一截，而且模型做大也有帮助，但没有加数据那么管用。作者强调这是基准未饱和区间里的局部经验趋势，而且简单题上强模型接近天花板时，局部斜率会被压扁，不能当成全局定律硬套。

回过头想，把这套联合律再接上 Chinchilla 风格的预训练损失公式，就能给还没训过的配方打分，同时直接扫出算力最优前沿。

从这个角度看，外推与实测前沿接近。最优 RL 占比随总算力升高，而且对应的预训练 token 分配，相对「同等预训练算力下的 Chinchilla 最优」没有系统性偏多或偏少。作者的结论可以概括成三句，也就是预训练通过「更低损失 → 更高后 RL 水平」和「更多数据 → 更快 RL 爬坡」两条路径影响 RL ，而且 pass@1 更吃 RL ， pass@k 更吃预训练，而且小预算时先把底子做扎实，预算变大后再按比例加 RL 。这和不少团队一上来就把八九成预算砸给 RL 的习惯正好相反，也就是预算不够大时，多做几步预训练，往往比多跑几千步 GRPO 更划算。

大家知道，RL 到底改了策略的哪一块社区里有两种对立叙事，也就是一种说 RL 主要锐化基座已偏好的推理模式（大 k 时基座 pass@k 未必输），而且另一种说 RL 能组合出新技能了。但是我觉得，棋盘试验台的好处是，也就是每一步都能看到合法着法上的概率怎么重新分配。

有意思的是，作者先检验「 RL 是否等于对 SFT 做幂次锐化」，也就是正确着法本来就略领先时，再把领先项的概率继续抬高、把其余选项压下去，形式写成。全局拟合斜率确实在训练中变大，说明平均在变尖，而且但用一条统一曲线去套所有局面并不准，不同局面实际发生的变化有很大一部分解释不了（统计上体现为偏低），很难用一次全局调温度概括。

其实看这直接解释了 Figure 2 里 pass@1 与 pass@16 的分叉，也就是概率在往「当前更可能对的一条」集中，覆盖面不一定变宽，而且难题上还在强化错误下法。若希望大 k 也持续变好，需要压错误放大、扩大正确解的支撑集，单靠把现有策略削尖不够。

为什么说推理轨迹结构上， RL 更像在加宽搜索、提高候选着法质量，最大深度变化不大，而且模型仍很难在大约 5 步之后找回正确的后续走法。作者据此建议，也就是未来合成 SFT 数据可以更有意识地鼓励更深、更系统的搜索，避免只堆宽度。

回过头想，棋盘上的规律，数学文本里也能看见这套结论未必只是棋盘巧合了。但是我觉得，为了检查，作者用 1B 的 OLMo-2 ，在约 200B token 的数学向混合语料上预训练（约 70% Nemotron-CC-Math ， 30% Dolma3 ），沿途取出 10B–200B 的 14 个检查点，而且再经 NuminaMath-CoT 上一轮 SFT ，然后在 GSM8K 、 MATH 、 DeepScaler 混合题上做 RL ，用 pass@1 评估。

近似线性变陡，形态与棋盘结果同向。

大家知道，任务格式、数据分布、训练配方都不同，至于同一种预测结构仍出现，其实就是预训练更久的检查点，在固定 RL 算力下终点更高， RL 曲线也更陡。这只是定性迁移证据，但说明「预训练性质 → RL 曲线」的接口，未必是棋盘特例。

有意思的是，边界与判断这套结论有明确适用边。棋的动作可核验、数据可筛选，归因干净，而且外推到开放文本时，奖励噪声和动作歧义都会更大。斜率律只在基准未饱和的局部成立，而且简单题见顶后，不能再用同一斜率讲故事。算力用 FLOPs 做分配单位，有利于比算法账，但实际运行时间（墙钟时间）还会吃系统开销，安排训练计划时不能把两者混为一谈。

说到底，即便如此，对「还要不要继续靠大量人类数据打底、以及经验反馈能不能替代先验」这类争论，这篇给出的是一张可计算的账，也就是 RL 需要足够强的预训练初始化才会有效，而且预算变大后，最优配方里 RL 的份额应上升，而且同时 RL 会放大正确模式，也会在难题上加固错误模式。对照当下不少团队「预训练随便糊、 RL 硬堆步数」的打法，至于这更像一组反例，其实就是底子不够时， GRPO 再多跑几千步也补不齐。更值得试的，或许是交错安排预训练与 RL ，用来及专门对付错误模式放大的后训练目标。
