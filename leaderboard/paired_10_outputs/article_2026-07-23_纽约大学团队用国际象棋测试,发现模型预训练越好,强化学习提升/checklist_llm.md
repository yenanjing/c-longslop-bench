现实里谈大模型推理，很多人默认——算力就得往后训练砸。
用对错能自动判定的奖励做 RL。
另一边呢，预训练还在继续加数据、加参数。
两边各有各的规模定律。
中间却缺一张量化对照。
预训练选得好不好，到底怎么改变后面每一分 RL 算力的回报？
RL 又究竟在改策略的哪一块？
说实话，这两个问题不好答。

在真实大模型上回答，难。
预训练语料又大又杂，行为很难归因。
再把预训练和 RL 一起做算力扫描，成本几乎扛不住啊。
纽约大学主导的这项工作，换了条路。
把国际象棋当可控试验台。
完整复刻今天常见的大模型训练流程。
在 5M 到 1B 参数上，把预训练和 RL 怎么互相影响，量化清楚。

为什么偏偏用棋盘？
讲道理，棋太适合做严谨对照了。
动作空间小。
对错可核验。
每一步着法，都能对照引擎或标准答案判定。
推理轨迹里每一步都透明。
不像自然语言，往往只剩个最终答案对不对。
人类对局数据量也大，还能按需筛子集。
作者从 Lichess 收了约 54B token 的 Blitz/Rapid 对局。
按 Elo、对局长度做子采样，想要啥筛啥。
小模型就有可测的棋力变化。
换参数规模，换预训练 token，换 RL 步数，下游都能看出差别。
算力扫描才做得出来。

论文目标很明确。
隔离「预训练规模」和「可验证 RL」怎么互相作用。
不追求最强下棋模型。

流程分三段，刻意照着现在大模型训练的常见习惯来。

预训练。
把棋局编成四元组 token——棋子、起点、终点、特殊标记。
词表只有 81。
模型学的是人类对局的下一步预测。

监督微调（SFT）。
在谜题上训练。
预训练模型只见过着法序列，没有显式推理。
作者不借助外部搜索工具。
改让模型自己写「思考」。
从预训练策略采样多条候选后续走法。
按公共前缀合成树。
再深度优先序列化成 <T>…</T> 推理轨迹。
最后提交正解着法。
思考内容还是棋步 token，不用自然语言。

强化学习。
从 SFT 策略出发。
在谜题环境用二元结果奖励。
整条正确解法，一步接一步全走对，才得 1。
否则 0。
优化器用 GRPO，一种相对组内基线估计优势的策略优化方法。
评估用 1480 道战术谜题。
按难度分 B1–B5 五档，B1 最易，B5 最难。
主文汇总指标多看 B1–B4。
最难的 B5，留给机制分析。

对照实验还说明一件事。
只 SFT 目标着法，pass@1 会涨，但 pass@8/16 几乎不动。
加上合成推理轨迹后，各 pass@k 一起改善。
后续 RL 都从这个设定起步。

算力怎么分？
前沿上，RL 占比会升高。
固定总 FLOPs 和模型大小。
预训练多吃一点 token，初始化更强，但留给 RL 的算力更少。
作者在 20M、50M、200M、680M 上扫多档预训练检查点。
各自做完同一套 SFT。
再跑 1000–5000 步 RL。
画出固定预算下的帕累托前沿。
也就是同样这么多算力，能拿到的最好成绩连成的那条线。
落在线之外的配方，都是算力没花在更值的地方。

看 pass@1，也就是一次采样就算对。
有三点很清楚。

RL 几乎总在抬高 pass@1，而且训练越久越高。
预算小的时候，前沿更爱选「预训练更多、RL 更少」的点。
说明早期 RL 严重受初始化拖累。
预训练基础差的模型，多堆 RL，也补不回预训练不足。
预算变大后，前沿上的 RL 占比抬升。
比如 20M 模型上，RL 占比从约 5% 走到约 32%。

pass@16 呢，采样 16 次里至少对一次，就混杂得多。
小模型上，RL 前期还能拉一把。
更大模型上，曲线接近平坦，有时还略降。
这时候再加预训练，往往比把同样算力继续扔给 RL 更划算。
这跟「RL 主要抬 pass@1、对大 k 覆盖帮助有限」的已有观察一致。
后文机制节会解释原因。

联合 scaling。
预训练 loss 能预测后 RL 表现。
前沿行为，引出第二个问题。
预训练侧的性质，能不能预测一段 RL 曲线会长成什么样。

已有工作常把固定模型的 RL 表现，拟成算力上的 sigmoid。
上渐近线是「无限 RL 天花板」。
但总预算固定时，多数 run 只落在未饱和的前半段。
天花板估不稳。
作者于是对这段做一阶近似，写成对数线性形式。

这里 φ 是参数量，D 是预训练 token 数，C 是 RL 算力。
A 是参考算力点上的表现。
α 是「RL 算力每增加一个数量级，奖励涨多少」的局部斜率。
说白了，在拟合区间里，RL 算力每乘 10，pass@1 大约固定加 α。

预训练损失大致定了后 RL 能爬到多高。
预训练数据量大致定了这条曲线爬多快。
分开来看。

水平由预训练损失决定。
在中等难度 B3–B4 上，预训练验证损失越低，同一 RL 算力下的后 RL pass@1 越高。
参考算力从 10^16 提到 10^17 时，两者的排序一致性——越接近 -1，说明「损失越低、表现越好」越稳——从约 -0.93 紧到约 -0.99。
高 RL 算力下的后 RL 表现，比「刚做完 SFT、还没 RL」的起点，更贴预训练损失。
预训练的影响，会在 RL 过程中被放大。

斜率主要由预训练数据量决定。
α 与 D 正相关（Pearson）。
联合拟合也支持这点。
说白了，数据每多一个量级，RL 的爬坡曲线就明显陡一截。
模型做大也有帮助，但没加数据那么管用。
作者强调，这是基准未饱和区间里的局部经验趋势。
简单题上强模型接近天花板时，局部斜率会被压扁。
不能当成全局定律硬套。

把这套联合律，再接上 Chinchilla 风格的预训练损失公式，就能给还没训过的配方。

外推结果，和实测前沿接近。
最优 RL 占比随总算力升高。
对应的预训练 token 分配，相对「同等预训练算力下的 Chinchilla 最优」，没有系统性偏多或偏少。
作者的结论，三句话能概括。
预训练通过两条路径影响 RL——更低损失带来更高后 RL 水平，更多数据带来更快 RL 爬坡。
pass@1 更吃 RL，pass@k 更吃预训练。
小预算时先把底子做扎实，预算变大后再按比例加 RL。
你看，这跟不少团队一上来就把八九成预算砸给 RL 的习惯，正好相反。
预算不够大时，多做几步预训练，往往比多跑几千步 GRPO 更划算。

RL 到底改了策略的哪一块？
社区里有两种对立叙事。
一种说 RL 主要锐化基座已偏好的推理模式，大 k 时基座 pass@k 未必输。
另一种说 RL 能组合出新技能。
棋盘试验台的好处是，每一步都能看到合法着法上的概率怎么重新分配。

作者先检验「RL 是不是等于对 SFT 做幂次锐化」。
也就是正确着法本来就略领先时，再把领先项的概率继续抬高、把其余选项压下去。
形式写成 p 的 1/β 次方。

全局拟合斜率 β 确实在训练中变大，说明平均在变尖。
但用一条统一曲线去套所有局面，并不准。
不同局面实际发生的变化，有很大一部分解释不了——统计上体现为 R² 偏低。
很难用一次全局调温度概括。

于是按「正解着法如何进出 top-3」，把局部更新分成几类。
文中重点看三类。

正解放大。
正解已在 top-k，训练继续加强。

尾部发现。
正解原先概率低于 0.05，被抬进 top-k。

错误模式放大。
正解仍在门外，原先偏好的错着被继续加强。

结果按难度，呈现出两种不同规律。
简单谜题上，RL 主要放大 SFT 已经倾向的正确着法。
困难谜题上，它既能把几乎从未被偏好的正确着法从尾部捞上来，也会把错误着法越训越自信。
一张难例更直观。

难例（B5）。
正解 b6e3。
预训练几乎全押在错着 d6e5。
SFT 后概率摊开，但正解仍低。
RL 过程中正解升到首位——尾部发现。
同时另一错着 b6b4 也保有不少概率权重——错误放大。

这直接解释了 Figure 2 里 pass@1 与 pass@16 的分叉。
概率在往「当前更可能对的一条」集中。
覆盖面不一定变宽。
难题上，还在强化错误下法。
若希望大 k 也持续变好，得压错误放大、扩大正确解的支撑集。
单靠把现有策略削尖，不够啊。

推理轨迹结构上，RL 更像在加宽搜索、提高候选着法质量。
最大深度变化不大。
模型仍很难在大约 5 步之后找回正确的后续走法。
作者据此建议，未来合成 SFT 数据，可以更有意识地鼓励更深、更系统的搜索，别只堆宽度。

棋盘上的规律，数学文本里也能看见。
这套结论，未必只是棋盘巧合。
为了检查，作者用 1B 的 OLMo-2，在约 200B token 的数学向混合语料上预训练——约 70% Nemotron-CC-Math，30% Dolma3。
沿途取出 10B–200B 的 14 个检查点。
再经 NuminaMath-CoT 上一轮 SFT。
然后在 GSM8K、MATH、DeepScaler 混合题上做 RL，用 pass@1 评估。

近似线性变陡，形态跟棋盘结果同向。
任务格式、数据分布、训练配方，全不一样。
同一种预测结构，还是出现了。
预训练更久的检查点，在固定 RL 算力下终点更高，RL 曲线也更陡。
这只是定性迁移证据。
但说明「预训练性质 → RL 曲线」这个接口，未必是棋盘特例。

边界与判断。
这套结论，有明确的适用边。
棋的动作可核验，数据可筛选，归因干净。
外推到开放文本时，奖励噪声和动作歧义都会更大。
斜率律只在基准未饱和的局部成立。
简单题见顶后，不能再用同一斜率讲故事。
算力用 FLOPs 做分配单位，有利于比算法账。
但实际运行时间——墙钟时间——还会吃系统开销。
安排训练计划时，可不能把两者混为一谈。

即便如此，对「还要不要继续靠大量人类数据打底、以及经验反馈能不能替代先验」这类争论，这篇给出的是一张可计算的账。
RL 需要足够强的预训练初始化，才会有效。
预算变大后，最优配方里 RL 的份额应上升。
同时 RL 会放大正确模式，也会在难题上加固错误模式。
对照当下不少团队「预训练随便糊、RL 硬堆步数」的打法，这更像一组反例。
底子不够时，GRPO 再多跑几千步也补不齐。
更值得试的，或许是交错安排预训练与 RL，以及专门对付错误模式放大的后训练目标。
