圣母大学团队整了个新玩意儿，叫 MemoHarness。

说白了，就是把 Agent harness 拆成六个能动的维度。再拿历史执行记录，针对每一道新题，单独改一版配置。结果呢？Terminal-Bench 成功率，比最强的固定 harness 基线高了 8.4 个百分点。0.722 涨到 0.806。

论文标题 MemoHarness: Agent Harnesses That Learn from Experience。Github 链接放文末了。

Terminal-Bench 测的是长程 shell 智能体。同一台机器，同一套工具。模型得在好几轮命令里，自己排错，自己收尾。

基座还是那个 GPT-5.3-Codex。成功率 0.722 到 0.806。多出来的 8.4 个百分点，主要来自哪儿？提示怎么拼，工具什么时候开，失败了怎么校验。说白了，就是 harness。

harness 是个啥？就是把基座大模型包成能真跑任务的 Agent 时，外面那层软件。上下文拼装、工具和检索接口、解码参数、多步编排、跨轮记忆、输出抽取和格式校验，都算。

业内经验是这样。模型和工具都不动，光改这层，端到端成功率能差出几十个百分点。

现有自动优化，多半只动其中一块。改提示词，或者改声明式调用流水线，再或者改多步工作流。搜完通常就定一版全局配置。上线之后，全站共用。

题目类型差得多的时候，平均分还不错的 harness，照样会稳定打挂某几类题。

Meta-Harness 那一类工作，会把 harness 代码本身当搜索对象。可结果还是训练期定稿，部署期复用。

MemoHarness 不一样。它动的是测试阶段。每来一道新题，就用冻结住的经验库，把全局 harness 改成这一题的专用版。改编过程不看标准答案，也不额外搜索。

它的做法是先搜全局 harness，再按题改一版。论文把一份 harness 写成六个可编辑控制面的笛卡尔积。

每一维管推理流水线里的一段。拼输入，调工具，解码，编排，记忆，输出。搜索不再去改一整坨黑盒提示，而是在这六个旋钮上做结构化编辑。

整体分两阶段。

训练期，在有标签的搜索集上反复试候选。每轮先按平均做对多少排序，打平了再挑更省 token 的。每次执行都把轨迹、得分、成本、维度诊断写进经验库。搜索策略自己也读这本库，根据当前 harness 和过往成败，提案下一版要在哪几个维度动刀。

测试期，经验库冻结。对新题只做一次检索加改编。捞相似的成功失败案例，按题型过滤的记录，还有蒸馏出来的全局规律，把训练得到的全局 harness 改成案例级。

这跟只看总分的黑盒搜索不一样。某次失败要是写明了「检索已开，但输出校验没拦住 JSON 格式」，下一轮碰到同类题，就会优先改 D6 输出处理。整段提示重写碰运气，通常更慢。

跟只改 system prompt 比，六维拆分让「下一刀改哪里」有了坐标。经验库里留的是「改过什么，栽在哪一维」。光看 leaderboard 分数，很难还原这种信息。

六个可改维度，按一次推理的时间顺序拆。

团队这么分。D1 管调用前怎么拼输入。D2 管工具和检索开不开。D3 管生成长度和采样。D4 管单次还是多步编排。D5 管轮与轮之间记什么。D6 管调用后怎么抽答案、校验格式。

格式总挂，就先动 D6。整段提示重写，通常更慢。

Table 1 列了六个维度，分别对应调用前拼输入、工具与检索、生成长度与采样、多步怎么串、多轮之间记什么，以及调用后怎么抽答案、校验格式。

六维会互相牵扯。一开检索，提示里就得多留证据位，生成预算可能加长，步骤可能从单次变多轮，结尾校验也得从「原样输出」改成「抽字段」。

所以每次跑完，不能只记对错。还得标主要失败维度、次要连带维度，再留一段自然语言分析。系统还盯着连续失败次数、近期正确率走势、分维度失败计数。

经验库是一对有类型区分的集合。案例层和全局层，各有自己的字段结构。

案例层是逐题执行记录。含相对上一版的配置差，轨迹，奖励，token 成本，还有诊断。诊断里写明成败、主失败维度、次要连带维度，以及一段自然语言分析。

全局层是每隔若干轮，从反复出现的失败里蒸馏规律。总结什么常有效，什么常失效，维度之间怎么互相牵扯。查询的时候，不把整库硬塞进上下文，而是按题目特征、失败统计和维度诊断，取有限几条。免得历史越积越多，把窗口撑爆。

搜索从最简配置起步。无示例，无结构化模板，无外部工具，单次确定性生成，不跨轮记忆，输出原样返回。

最终交付的每个组件，最好都能指回某次试跑。比如某条校验规则是哪轮格式失败后加上的。尽量少靠事后凭感觉写进提示。

正确率优先。token 只做平局决胜。

在配置下跑完案例，得到预测。搜索时的主奖励是任务指定的正确性指标，只在训练搜索时可见。次要成本是总 token 数，越小越好。调用次数和延迟会记进日志，但不进选型规则。美元费用事后按公开标价核算，也不参与搜索。

对候选，先算平均奖励和平均成本，再按字典序挑全局 harness。

意思很直接。先比谁做对得多。只有主奖励打平了，才挑更省 token 的那套。这样能避免搜索漂到「便宜但做错」的配置上。

做新题的时候怎么改，还不看答案。

测试时题面没有标准答案。系统把题指令编码成向量，用余弦相似度，从历史成功集和失败集里，各取最像的若干条。再加上按题型过滤的检索切片和全局规律，拼成测试证据，由控制器输出这一题的 harness。

然后只跑一轮就交卷。中间不重新搜索，也不根据对错再学一轮。

简单题继续走轻量路径。需要检索、多步编排、严格输出格式的题，只有检索到的历史经验支持时，才启用更重的流程。

要是事后有了评测标签，轨迹可以写回经验库，供以后复用。但当次评测不会触发再学习，也不会再搜索。这是故意的，为了防泄漏。

主结果，对照故意选得很强。

评测覆盖三类任务。长程 shell 智能体，Terminal-Bench。单次代码生成，LiveCodeBench。多步金融推理，FinanceAgent。

主对比在 Terminal-Bench 上，跟四个已发布或基准自带的 harness 共用同一套评测规则。报告的是验证集挑出的最终版，不拿训练过程中测试集上的峰值充数。

四个对照里，Codex（0.722）已经是面向终端的专用 harness，不是弱提示基线。Claude Code、Terminus、OpenCode 分数更低。MemoHarness 相对它们，高出 0.250 到 0.445。

说实话，读数要分两类。Codex 和 MemoHarness 共用 GPT-5.3-Codex，分差更接近「只换 harness」。厂商整包产品，模型、工具、权限绑在一起。这只能读成「同一考场规则下，它公布的那套用法」好不好。不能当成拆掉 harness 后的纯模型对决。

三个源基准上，交付 harness 相对初始基线都有提升。

Terminal-Bench 0.722→0.806，涨了 8.4 个百分点。LiveCodeBench 0.900→0.967，涨了 6.7 个百分点。FinanceAgent 0.600→0.767，涨了 16.7 个百分点。

涨幅最大的是 FinanceAgent，基线留下的空间也最大。LiveCodeBench 已接近天花板，提升就小。

步骤多、失败方式也多的任务，更吃 harness 搜索。接近满分的单次代码生成，搜索多半只在很小的分数区间里蹭一点。

论文附录还做了「原子操作」层面的增益分析。哪些维度的哪类改动，更常跟着奖励上涨出现。这对理解「下一刀该改哪」，比只看总分有用多了。

换数据集、换模型，收益是选择性的。

把各源基准上搜到的最终 harness 原样迁到六个没见过的评测套件。基座仍然固定为 GPT-5.3-Codex。对照同一套未调优的 Codex 基线。

你看，Table 2 是跨数据集迁移。Terminal-Bench 源 harness，在最多套件上都能涨分。MMMLU +0.030，StrongReject +0.030，SWE-Bench Pro +0.059。已经接近满分的 HumanEvalFix 和 Reasoning-Gym-Easy，基本不动。

迁移有选择性。长程、偏工具的源任务，迁出去仍可能涨分。改得很保守的源配置，换到 LawBench 一类套件，会来回晃。

论文也写明了。还没把迁过去的 harness 拆成组件逐项验证。这个判断仍是初步的。

跨模型这边，用 GPT-5.3-Codex 搜出的 harness，直接套到六个其他模型，不重新搜索。

Table 3 是 Terminal-Bench 跨模型迁移。全部模型相对各自 Base 都上升，平均 +0.098。GLM-5 从 0.500 到 0.733，涨了 0.233。GPT-4.1 只涨了 0.038。

专有 API 和开源权重模型，都有收益。讲道理，这更像是搜到了「怎么取上下文、何时调工具、如何管中间状态、怎样收尾校验」这类流程习惯。要是只是某模型私有的提示口吻，换开源权重不该普遍上涨。

GPT-4.1 增益偏小，也符合「基座已经较稳时，harness 可改空间更窄」那个判断。不过还得靠更大的模型和任务集合来确认。

成本这块，多出来的输入，大半进了缓存。

在 Terminal-Bench 留出的 18 题正式评测集上，基座还是 GPT-5.3-Codex，按公开标价事后核算美元成本。

Table 4 说了。MemoHarness 输入 token 更高，14.18M，但其中 13.32M 是缓存。总费用 6.89 美元，低于 Codex 的 10.28 美元，也低于 Claude Code 的 9.51 美元。同时任务成功率还更高。Terminus 和 OpenCode 更便宜，准确率明显更低。

经验检索会推高原始输入 token。要是线上缓存命中差，或者提示几乎每题都变，6.89 美元这张账单，就不好直接拿去对标。

其实选型规则本身，仍只把原始 token 当打平时的第二标准，不用美元。这跟「训的时候尽量做对，费用事后另算」的设计是一致的。

边界和可借鉴的地方。

MemoHarness 把执行经验当成可复用的 harness 基建。六维拆分让失败能指到具体维度。经验库让搜索带着诊断。测试时再按题改编，部署就不必只剩一套全局配置。

在本文的评测规则下，相对对照的固定 harness，它有提升。换套件、换模型，收益是选择性的。大量检索上下文能进缓存时，额外费用也可控。

论文自己留的口子也很清楚。统计稳健性、组件级归因、完全无监督搜索、更大规模验证，还有上线后持续累积经验，都还没做完。

要是线上仍是全站一套 harness，先别急着上完整搜索。更划算的做法是这样。每次失败只标一个主因，检索、编排、校验里挑一个。再按题型记下「改过什么，分数有没有涨」。攒够几十条这种记录，再评估要不要做 MemoHarness 式的按题改编吧。
