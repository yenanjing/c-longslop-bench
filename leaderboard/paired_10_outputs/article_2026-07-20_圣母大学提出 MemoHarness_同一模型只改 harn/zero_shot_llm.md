圣母大学团队最近提出了 MemoHarness。它的思路是把 Agent harness 拆成六个可以分别调整的维度，再借助历史执行记录，为每一道新题单独改出一版配置。在 Terminal-Bench 上，这套方法的成功率比最强的固定 harness 基线高出 8.4 个百分点，从 0.722 升到了 0.806。

论文题为 MemoHarness: Agent Harnesses That Learn from Experience，Github 链接如下。

Terminal-Bench 考的是长程 shell 智能体：同一台机器、同一套工具，模型得在一连串命令里自己排错、自己收尾。基座同样用 GPT-5.3-Codex，成功率却从 0.722 提到了 0.806。多出来的这 8.4 个百分点，主要不靠模型，而靠提示怎么拼、工具什么时候开、失败之后怎么校验——说到底，靠的是 harness。

所谓 harness，就是把基座大模型包成真正能跑任务的 Agent 时，外面套的那层软件：上下文怎么拼装、工具和检索接口、解码参数、多步编排、跨轮记忆，以及输出抽取和格式校验。业内的经验是，模型和工具都不动，只改这一层，端到端成功率就能差出几十个百分点。

现有的自动优化大多只盯着其中一块：要么改提示词，要么改声明式调用流水线，要么改多步工作流。搜完通常定一版全局配置，上线后全站共用。可题目类型一杂，一份平均分还不错的 harness，往往就在某几类题上稳定翻车。Meta-Harness 一类工作把 harness 代码本身当搜索对象，但仍是训练期定稿、部署期复用。MemoHarness 的差别落在测试阶段——面对每道新题，它用一份冻结的经验库，把全局 harness 改成这道题的专用版。改编时不看标准答案，也不做额外搜索。

论文把一份 harness 写成六个可编辑控制面的笛卡尔积。每一维管推理流水线里的一段：拼输入、调工具、解码、编排、记忆、输出。搜索不再是改一整坨黑盒提示，而是在这六个旋钮上做结构化编辑。

整体分两阶段。训练期在有标签的搜索集上反复试候选：每轮先按平均做对多少排序，打平时再挑更省 token 的；每次执行都把轨迹、得分、成本和维度诊断写进经验库。搜索策略本身也读这本库，根据当前 harness 和过往的成败，提案下一版该动哪几个维度。

到了测试期，经验库冻结。对新题只做一次检索和改编：捞出相似的成功、失败案例，按题型过滤过的记录，还有蒸馏出的全局规律，把训练得到的全局 harness 改成案例级版本，然后跑一轮就出答案。

这跟只看总分的黑盒搜索不一样。假如某次失败写明「检索已经开了，但输出校验没拦住 JSON 格式」，下一轮碰上同类题，系统就会优先去改 D6 的输出处理；相比之下，整段提示重写碰运气通常慢得多。和只改 system prompt 相比，六维拆分让「下一刀改哪里」有了坐标。经验库里留下的是「改过什么、栽在哪一维」，这种信息光看 leaderboard 分数是还原不出来的。

六个维度按一次推理的先后顺序来拆，搜索只在这些旋钮上拧。D1 管调用前怎么拼输入；D2 管工具和检索开不开；D3 管生成长度和采样；D4 管单次还是多步编排；D5 管轮与轮之间记什么；D6 管调用后怎么抽答案、校验格式。Table 1 列出的，正是这六个维度分别对应的环节：调用前拼输入、工具与检索、生成长度与采样、多步怎么串、多轮之间记什么，以及调用后怎么抽答案、校验格式。格式总挂，就先动 D6。

六维之间会互相牵扯。一开检索，提示里就得留出证据位，生成预算可能要加长，步骤可能从单次变成多轮，结尾校验也得从「原样输出」改成「抽字段」。所以每轮跑完不能只记对错，还要标出主要失败维度和次要连带维度，再留一段自然语言分析。系统还会跟踪连续失败次数、近期正确率走势，以及分维度的失败计数。

经验库是一对带类型区分的集合，案例层和全局层各有自己的字段结构。

案例层是逐题的执行记录，包含相对上一版的配置差、轨迹、奖励、token 成本和诊断。诊断里写清成败、主失败维度、次要连带维度，外加一段自然语言分析。

全局层则是每隔若干轮，从反复出现的失败里蒸馏出的规律：什么做法常有效、什么常失效、维度之间怎么互相牵扯。查询时不会把整库硬塞进上下文，而是按题目特征、失败统计和维度诊断只取有限几条，免得历史越攒越多、把窗口撑爆。

搜索从最简配置起步：无示例、无结构化模板、无外部工具、单次确定性生成、不跨轮记忆、输出原样返回。最终交付的每个组件，最好都能指回某一次试跑——比如某条校验规则是哪轮格式失败后加上的——尽量少靠事后凭感觉往提示里补。

选型上，正确率优先，token 只当平局时的决胜砝码。在某一配置下跑完案例，拿到预测，搜索看两个量：主奖励是任务指定的正确性指标，只在训练搜索时可见；次要成本是总 token 数，越小越好。调用次数和延迟会记进日志，但不进入选型规则；美元费用是事后按公开标价核算的，同样不参与搜索。

对候选，先算平均奖励和平均成本，再按字典序挑出全局 harness。意思很直白：先比谁做对得多，只有主奖励打平，才挑更省 token 的那套。这样就能避免搜索漂到「便宜但做错」的配置上。

到了新题上怎么改，却不看答案——测试时题面本来就没有标准答案。系统把题指令编码成向量，用余弦相似度从历史成功集和失败集里各取最像的若干条，再补上按题型过滤的检索切片和全局规律，拼成测试证据，由控制器输出这道题的 harness，然后只跑一轮就交卷。中间不重新搜索，也不根据对错再学一轮。

简单题继续走轻量路径。只有检索到的历史经验确实支持，才为需要检索、多步编排或严格输出格式的题启用更重的流程。如果事后拿到了评测标签，轨迹可以写回经验库供以后复用，但当次评测不会触发再学习或再搜索——这是刻意做的泄漏防护。

主结果方面，对照组选得故意很强。评测覆盖三类任务：长程 shell 智能体（Terminal-Bench）、单次代码生成（LiveCodeBench）、多步金融推理（FinanceAgent）。主对比放在 Terminal-Bench 上，与四个已发布或基准自带的 harness 共用同一套评测规则；报告的是验证集挑出的最终版，不拿训练过程中测试集上的峰值充数。

四个对照里，Codex（0.722）本身已经是面向终端的专用 harness，不是弱提示基线；Claude Code、Terminus、OpenCode 分数更低，MemoHarness 相对它们高出 0.250 到 0.445。读这组数要分两类看：Codex 和 MemoHarness 共用 GPT-5.3-Codex，分差更接近「只换 harness」；厂商的整包产品则把模型、工具、权限绑在一起，只能读成「同一考场规则下，它公布的那套用法」好不好，不能当成拆掉 harness 后的纯模型对决。

在三个源基准上，交付的 harness 相对初始基线都有提升：Terminal-Bench 从 0.722 到 0.806（+8.4 个百分点），LiveCodeBench 从 0.900 到 0.967（+6.7 个百分点），FinanceAgent 从 0.600 到 0.767（+16.7 个百分点）。涨幅最大的是 FinanceAgent，基线留下的空间也最大；LiveCodeBench 已经接近天花板，提升自然更小。

步骤多、失败方式也多的任务，更吃 harness 搜索；接近满分的单次代码生成，搜索多半只在很小的分数区间里蹭一点。论文附录还做了「原子操作」层面的增益分析：哪些维度的哪类改动，更常伴随着奖励上涨出现。这对判断「下一刀该改哪」，比只看总分有用得多。

换数据集、换模型之后，收益是有选择性的。把各源基准上搜到的最终 harness 原样迁到六个没见过的评测套件，基座仍固定为 GPT-5.3-Codex，对照同一套未调优的 Codex 基线。

Table 2 是跨数据集迁移的结果：Terminal-Bench 上搜到的源 harness，在最多套件上都能涨分（MMMLU +0.030、StrongReject +0.030、SWE-Bench Pro +0.059）；而已经接近满分的 HumanEvalFix 和 Reasoning-Gym-Easy 基本不动。

迁移确实挑任务。长程、偏工具的源任务迁出去仍可能涨分；改得很保守的源配置，换到 LawBench 一类套件就会来回晃。论文也写明：还没把迁过去的 harness 拆成组件逐项验证，这个判断仍是初步的。

跨模型方面，用 GPT-5.3-Codex 搜出的 harness 直接套到另外六个模型上，不再重新搜索。Table 3 给出 Terminal-Bench 的跨模型迁移结果：全部模型相对各自的 Base 都有上升，平均 +0.098；GLM-5 从 0.500 涨到 0.733（+0.233），GPT-4.1 只涨了 0.038。

专有 API 和开源权重的模型都有收益，这更像是搜到了「怎么取上下文、何时调工具、如何管中间状态、怎样收尾校验」这类流程习惯；要是只摸到了某个模型私有的提示口吻，换到开源权重不该普遍上涨。GPT-4.1 增益偏小，也符合「基座已经较稳时，harness 可改空间更窄」的判断，但仍需更大模型和任务集合来确认。

成本方面，多出来的输入大半进了缓存。在 Terminal-Bench 留出的 18 题正式评测集上，基座仍是 GPT-5.3-Codex，美元成本按公开标价事后核算。

Table 4 显示，MemoHarness 的输入 token 更高（14.18M），但其中 13.32M 是缓存命中；总费用 6.89 美元，低于 Codex 的 10.28 美元和 Claude Code 的 9.51 美元，同时任务成功率还更高。Terminus 和 OpenCode 更便宜，准确率却明显低一截。

经验检索会推高原始输入 token。如果线上缓存命中差，或者提示几乎每题都变，6.89 美元这张账单就不好直接拿去对标。选型规则本身仍只把原始 token 当作打平时的第二标准，不用美元，这和「训的时候尽量做对、费用事后另算」的设计是一致的。

最后是边界和可借鉴处。MemoHarness 把执行经验当成可复用的 harness 基建：六维拆分让失败能指到具体维度，经验库让搜索带上诊断，测试时再按题改编，部署就不必只剩一套全局配置。在本文的评测规则下，它相对对照的固定 harness 确有提升；换套件、换模型时，收益是选择性的；当大量检索上下文能进缓存，额外费用也可控。

论文自己留的口子同样清楚：统计稳健性、组件级归因、完全无监督搜索、更大规模验证，以及上线后持续累积经验，都还没做完。如果线上现在还是全站一套 harness，先别急着上完整搜索。更划算的做法是，每次失败只标一个主因（检索、编排还是校验），并按题型记下「改过什么、分数有没有涨」。等攒够几十条这样的记录，再评估要不要做 MemoHarness 式的按题改编。
