圣母大学团队提出的 MemoHarness，说的是把 Agent harness 拆成六个可改维度，用历史执行记录在每道新题上单独改一版配置，Terminal-Bench 成功率相对最强固定 harness 基线提升了 8.4 个百分点，从 0.722 提到了 0.806。

Terminal-Bench 测的是长程 shell 智能体，说的是同一台机器、同一套工具，模型要在多轮命令里自己排错、自己收尾。同一个基座 GPT-5.3-Codex，成功率从 0.722 到 0.806，多出来的 8.4 个百分点，主要来自提示怎么拼、工具何时开、失败后怎么校验，说的其实就是 harness 这一层。

harness 说的是把基座大模型包成能真正跑任务的 Agent 时，外面那层软件，也就是上下文拼装、工具与检索接口、解码参数、多步编排、跨轮记忆、输出抽取与格式校验。业界的经验是，模型和工具都不变，只改这层，端到端成功率能差出几十个百分点来。

现有自动优化多半只动其中一块，也就是改提示词、改声明式调用流水线，或者改多步工作流。搜完通常定一版全局配置，上线后全站共用。题目类型差很多的时候，平均分不错的 harness 还是会稳定打挂某几类题。Meta-Harness 一类工作会把 harness 代码本身当搜索对象，但结果仍是训练期定稿、部署期复用。MemoHarness 的差别在测试阶段，说的是对每道新题，用冻结的经验库把全局 harness 改成这一题专用版，改编过程不看标准答案，也不额外搜索。

先搜全局 harness，再按题改一版。论文把一份 harness 写成六个可编辑控制面的笛卡尔积，意思就是这么搭出来的。

每一维。管推理流水线里的一段：拼输入、调工具、解码、编排、记忆、输出。搜索不再改一整坨黑盒提示，而是在这六个旋钮上结构化编辑。

沿着这六个旋钮的编辑往下说，整体分两阶段。训练期在有标签的搜索集上反复试候选，每一轮先按平均做对多少排序，打平了再挑更省 token 的，每次执行都把轨迹、得分、成本、维度诊断写进经验库。搜索策略本身也读这本库，根据当前 harness 和过往成败，提案下一版要在哪几个维度动刀。

测试期经验库冻结。对新题只做一次检索与改编，说的是捞相似的成功案例和失败案例、按题型过滤的记录，以及蒸馏出的全局规律，把训练得到的全局 harness 改成案例级。

这和只看总分的黑盒搜索不同。某次失败若写明「检索已开但输出校验没拦住 JSON 格式」，下一轮同类题会优先改 D6 输出处理，整段提示重写碰运气通常更慢。和只改 system prompt 相比，六维拆分让「下一刀改哪里」有坐标；经验库里留的是「改过什么、栽在哪一维」，单看 leaderboard 分数很难还原这种信息。

六个可改维度是按一次推理的时间顺序拆的。团队按一次推理先后拆成六维，搜索只在这些旋钮上拧。D1 管调用前怎么拼输入，D2 管工具和检索开不开，D3 管生成长度和采样，D4 管单次还是多步编排，D5 管轮与轮之间记什么，D6 管调用后怎么抽答案、校验格式。格式总挂就先动 D6，整段提示重写通常更慢。

Table 1 里列的是六个维度分别对应的东西，调用前拼输入、工具与检索、生成长度与采样、多步怎么串、多轮之间记什么，以及调用后怎么抽答案、校验格式。

六维会互相牵扯，说的是一开检索，提示里就要多留证据位，生成预算可能加长，步骤可能从单次变多轮，结尾校验也要从「原样输出」改成「抽字段」。所以每次跑完不能只记对错，还要标主要失败维度、次要连带维度，并留一段自然语言分析，系统还跟踪连续失败次数、近期正确率走势、分维度失败计数。

为了避免把窗口撑爆，搜索从最简配置起步，也就是无示例、无结构化模板、无外部工具、单次确定性生成、不跨轮记忆、输出原样返回。这里想说的是，最终交付的每个组件，最好都能指回某次试跑，比如某条校验规则是哪轮格式失败后加上的，尽量少靠事后凭感觉写进提示。

主结果这块，对照是故意选得很强的，说的是把标杆立得高高的。评测覆盖了三类任务，也就是长程 shell 智能体的 Terminal-Bench、单次代码生成的 LiveCodeBench，还有多步金融推理的 FinanceAgent。主对比放在 Terminal-Bench 上做，跟四个已经发布或者基准自带的 harness 共用同一套评测规则。报告出来的是验证集挑出的最终版，不拿训练过程中测试集上的峰值来充数。

四个对照里面，Codex 是 0.722，它已经是面向终端的专用 harness 了，不是那种弱提示基线。Claude Code、Terminus、OpenCode 的分数更低一些，MemoHarness 相对它们能高出 0.250 到 0.445。读数的时候得分成两类来看，说的是 Codex 跟 MemoHarness 共用 GPT-5.3-Codex，它们的分差更接近「只换 harness」这回事，但是厂商整包产品就不一样了，模型、工具、权限是绑在一起的，只能读成「同一考场规则下，它公布的那套用法」好不好，可不能当成拆掉 harness 之后的纯模型对决。

三个源基准上头，交付的 harness 相对初始基线都是有提升的，也就是 Terminal-Bench 从 0.722 涨到 0.806，多了 8.4 个百分点，LiveCodeBench 从 0.900 涨到 0.967，多了 6.7 个百分点，FinanceAgent 从 0.600 涨到 0.767，多了 16.7 个百分点。涨幅最大的是 FinanceAgent，它基线留下的空间也是最大的。LiveCodeBench 呢，已经接近天花板了，提升自然就小一些。

步骤多、失败方式也多的任务，是更吃 harness 搜索的。反过来接近满分的单次代码生成，搜索多半只在很小的分数区间里蹭那么一点。论文附录还做了「原子操作」层面的增益分析，说的是哪些维度上的哪类改动，更常跟着奖励上涨一块儿出现。这比光盯着总分，对理解「下一刀该改哪」要有用得多。

换数据集、换模型这一节，收益是有选择性的，也就是挑着来的。具体来说，是把各源基准上搜到的最终 harness 原样迁到六个没见过的评测套件上，基座还是固定成 GPT-5.3-Codex，对照的是同一套没调优的 Codex 基线。

Table 2 讲的是跨数据集迁移。说的是拿 Terminal-Bench 源的那套 harness，它在最多的套件上都能涨分，MMMLU 涨 0.030，StrongReject 也是 0.030，SWE-Bench Pro 涨 0.059。而已经接近满分的 HumanEvalFix 和 Reasoning-Gym-Easy，就基本不动了。

迁移是有选择性的，说的是长程的、偏工具的源任务，迁出去还是可能涨分的。但是改得很保守的源配置，换到 LawBench 那一类套件，就会来回晃了。论文也写明了，还没有把迁过去的 harness 拆成组件逐项去验证，所以这个判断仍然是初步的。

跨模型方面，用 GPT-5.3-Codex 搜出的 harness 直接套到六个其他模型，不重新搜索。

专有 API 与开源权重模型都有收益，更像是搜到了「怎么取上下文、何时调工具、如何管中间状态、怎样收尾校验」这类流程习惯；若只是某模型私有提示口吻，换开源权重不该普遍上涨。 GPT-4.1 增益偏小，也符合「基座已经较稳时， harness 可改空间更窄」的判断，但仍需更大模型与任务集合确认。

说到成本啊，它讲的是那多出来的输入，大半都进了缓存了。在 Terminal-Bench 留出的 18 题正式评测集上，拿同一个基座 GPT-5.3-Codex 来看，按公开标价事后核算了一下美元成本。

这组数据见 Table 4：MemoHarness 输入 token 更高（ 14.18M ），但其中 13.32M 为缓存；总费用 ＄ 6.89 ，低于 Codex （＄ 10.28 ）与 Claude Code （＄ 9.51 ），同时任务成功率更高。 Terminus 、 OpenCode 更便宜，但准确率明显更低。

经验检索会推高原始输入 token ；若线上缓存命中差、或提示几乎每题都变，＄ 6.89 这张账单就不好直接拿去对标。选型规则本身仍只把原始 token 当打平时的第二标准，不用美元，这和「训的时候尽量做对，费用事后另算」的设计一致。

顺着刚才的费用往下说，这会儿咱看看边界和可借鉴的地方。说的是 MemoHarness 把执行经验，当成了可以复用的 harness 基建了，也就是六维拆分让失败能指到具体的维度，经验库让搜索带上了诊断，测试的时候再按题改编，部署起来就不必只剩一套全局配置了。在本文的评测规则下，相对对照的固定 harness 是有提升的；不过换套件、换模型的时候，收益就是选择性的了；等大量检索上下文都能进缓存了，那额外费用也是可控的。

论文自己留的口子，同样说得挺清楚，也就是统计稳健性、组件级归因、完全无监督搜索、更大规模验证，还有上线后持续累积经验，这些都还没做完呢。要是线上还是全站一套 harness，先别急着上完整的搜索。更划算的做法是，每次失败只标一个主因，检索也好、编排也好、校验也好，然后按题型记下『改过什么、分数有没有涨』。攒够几十条这样的记录，再评估要不要做 MemoHarness 式的按题改编。
