回过头想，Terminal-Bench 测的是长程 shell 智能体，也就是同一台机器、同一套工具，模型要在多轮命令里自己排错、自己收尾了。其实换个角度看，同一基座 GPT-5.3-Codex ，成功率从 0.722 到 0.806 ，多出来的 8.4 个百分点，主要来自提示怎么拼、工具何时开、失败后怎么校验，也就是 harness 。

从这个角度看，harness指把基座大模型包成能真正跑任务的 Agent 时，至于外面那层软件，其实就是上下文拼装、工具与检索接口、解码参数、多步编排、跨轮记忆、输出抽取与格式校验。业界经验是，模型和工具都不变，只改这层，端到端成功率能差几十个百分点。

大家知道，现有自动优化多半只动其中一块其实在于，改提示词、改声明式调用流水线，或改多步工作流。搜完通常定一版全局配置，上线后全站共用。题目类型差很多时，平均分不错的 harness 仍会稳定打挂某几类题。 Meta-Harness 一类工作会把 harness 代码本身当搜索对象，但结果仍是训练期定稿、部署期复用。 MemoHarness 的差别在测试阶段，也就是对每道新题，用冻结的经验库把全局 harness 改成这一题专用版。改编过程不看标准答案，也不额外搜索。

表面上看，整体分两阶段。训练期在有标签的搜索集上反复试候选，也就是每轮先按平均做对多少排序，打平时再挑更省 token 的，而且每次执行都把轨迹、得分、成本、维度诊断写进经验库。搜索策略本身也读这本库，根据当前 harness 和过往成败，提案下一版要在哪几个维度动刀。

换句话讲，测试期经验库冻结了。但是我觉得，对新题只做一次检索与改编，也就是捞相似的成功/失败案例、按题型过滤的记录、以及蒸馏出的全局规律，把训练得到的全局 harness改成案例级，然后执行一轮出答案。

真正关键的地方在于，这和只看总分的黑盒搜索不同。某次失败若写明「检索已开但输出校验没拦住 JSON 格式」，下一轮同类题会优先改 D6 输出处理，整段提示重写碰运气通常更慢。和只改 system prompt 相比，六维拆分让「下一刀改哪里」有坐标，而且经验库里留的是「改过什么、栽在哪一维」，单看 leaderboard 分数很难还原这种信息。

其实看六个可改维度其实在于，按一次推理的时间顺序拆团队按一次推理先后拆成六维，搜索只在这些旋钮上拧。 D1 管调用前怎么拼输入，而且 D2 管工具和检索开不开，而且 D3 管生成长度和采样，而且 D4 管单次还是多步编排，而且 D5 管轮与轮之间记什么，而且 D6 管调用后怎么抽答案、校验格式。格式总挂就先动 D6 ，整段提示重写通常更慢。

回过头想，六维会互相牵扯其实在于，一开检索，提示里就要多留证据位，生成预算可能加长，步骤可能从单次变多轮，结尾校验也要从「原样输出」改成「抽字段」。所以每次跑完不能只记对错，还要标主要失败维度、次要连带维度，同时直接留一段自然语言分析，而且系统还跟踪连续失败次数、近期正确率走势、分维度失败计数。

表面上看，三个源基准上，交付 harness 相对初始基线都有提升，也就是 Terminal-Bench 0.722→0.806 （+8.4 个百分点）， LiveCodeBench 0.900→0.967 （+6.7 个百分点）， FinanceAgent 0.600→0.767 （+16.7 个百分点）。涨幅最大的是 FinanceAgent ，基线留下的空间也最大，而且 LiveCodeBench 已接近天花板，提升更小。

换句话讲，步骤多、失败方式也多的任务更吃 harness 搜索，而且接近满分的单次代码生成，搜索多半只在很小的分数区间里蹭一点了。但是我觉得，论文附录还做了「原子操作」层面的增益分析，也就是哪些维度的哪类改动，更常跟着奖励上涨出现。这对理解「下一刀该改哪」比只看总分更有用。

换句话讲，边界与可借鉴处 MemoHarness 把执行经验当成可复用的 harness 基建，也就是六维拆分让失败能指到具体维度，经验库让搜索带诊断，测试时再按题改编，部署就不必只剩一套全局配置了。其实换个角度看，在本文评测规则下，相对对照的固定 harness 有提升，而且换套件、换模型时收益是选择性的，而且大量检索上下文能进缓存时，额外费用也可控。

真正关键的地方在于，论文自己留的口子同样清楚其实在于，统计稳健性、组件级归因、完全无监督搜索、更大规模验证，用来及上线后持续累积经验，都还没做完。若线上仍是全站一套 harness ，先别急着上完整搜索。更划算的做法是，也就是每次失败只标一个主因（检索、编排、校验），同时直接按题型记下「改过什么、分数有没有涨」。攒够几十条这种记录，再评估要不要做 MemoHarness 式的按题改编。
