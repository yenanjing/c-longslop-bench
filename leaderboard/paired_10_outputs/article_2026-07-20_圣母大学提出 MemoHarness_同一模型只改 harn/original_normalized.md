圣母大学团队提出 MemoHarness ：把 Agent harness 拆成六个可改维度，用历史执行记录在每道新题上单独改一版配置， Terminal-Bench 成功率相对最强固定 harness 基线提升 8.4 个百分点（ 0.722→0.806 ）。

Terminal-Bench 测的是长程 shell 智能体：同一台机器、同一套工具，模型要在多轮命令里自己排错、自己收尾。同一基座 GPT-5.3-Codex ，成功率从 0.722 到 0.806 ，多出来的 8.4 个百分点，主要来自提示怎么拼、工具何时开、失败后怎么校验，也就是 harness 。

harness指把基座大模型包成能真正跑任务的 Agent 时，外面那层软件：上下文拼装、工具与检索接口、解码参数、多步编排、跨轮记忆、输出抽取与格式校验。业界经验是，模型和工具都不变，只改这层，端到端成功率能差几十个百分点。

现有自动优化多半只动其中一块：改提示词、改声明式调用流水线，或改多步工作流。搜完通常定一版全局配置，上线后全站共用。题目类型差很多时，平均分不错的 harness 仍会稳定打挂某几类题。 Meta-Harness 一类工作会把 harness 代码本身当搜索对象，但结果仍是训练期定稿、部署期复用。 MemoHarness 的差别在测试阶段：对每道新题，用冻结的经验库把全局 harness 改成这一题专用版。改编过程不看标准答案，也不额外搜索。

先搜全局 harness ，再按题改一版。论文把一份 harness 写成六个可编辑控制面的笛卡尔积：

每一维。管推理流水线里的一段：拼输入、调工具、解码、编排、记忆、输出。搜索不再改一整坨黑盒提示，而是在这六个旋钮上结构化编辑。

整体分两阶段。训练期在有标签的搜索集上反复试候选：每轮先按平均做对多少排序，打平时再挑更省 token 的；每次执行都把轨迹、得分、成本、维度诊断写进经验库。搜索策略本身也读这本库，根据当前 harness 和过往成败，提案下一版要在哪几个维度动刀。

测试期经验库冻结。对新题只做一次检索与改编：捞相似的成功/失败案例、按题型过滤的记录、以及蒸馏出的全局规律，把训练得到的全局 harness改成案例级。

这和只看总分的黑盒搜索不同。某次失败若写明「检索已开但输出校验没拦住 JSON 格式」，下一轮同类题会优先改 D6 输出处理，整段提示重写碰运气通常更慢。和只改 system prompt 相比，六维拆分让「下一刀改哪里」有坐标；经验库里留的是「改过什么、栽在哪一维」，单看 leaderboard 分数很难还原这种信息。

六个可改维度：按一次推理的时间顺序拆。团队按一次推理先后拆成六维，搜索只在这些旋钮上拧。 D1 管调用前怎么拼输入； D2 管工具和检索开不开； D3 管生成长度和采样； D4 管单次还是多步编排； D5 管轮与轮之间记什么； D6 管调用后怎么抽答案、校验格式。格式总挂就先动 D6 ，整段提示重写通常更慢。

Table 1 ：六个维度分别对应调用前拼输入、工具与检索、生成长度与采样、多步怎么串、多轮之间记什么，以及调用后怎么抽答案、校验格式。

六维会互相牵扯：一开检索，提示里就要多留证据位，生成预算可能加长，步骤可能从单次变多轮，结尾校验也要从「原样输出」改成「抽字段」。所以每次跑完不能只记对错，还要标主要失败维度、次要连带维度，并留一段自然语言分析；系统还跟踪连续失败次数、近期正确率走势、分维度失败计数。

主结果：对照故意选得很强。评测覆盖三类任务：长程 shell 智能体（ Terminal-Bench ）、单次代码生成（ LiveCodeBench ）、多步金融推理（ FinanceAgent ）。主对比在 Terminal-Bench 上，与四个已发布或基准自带的 harness 共用同一套评测规则；报告的是验证集挑出的最终版，不拿训练过程中测试集上的峰值充数。

四个对照里，Codex（ 0.722 ）已是面向终端的专用 harness ，不是弱提示基线；Claude Code、Terminus、OpenCode分数更低， MemoHarness 相对它们高出 0.250–0.445 。读数时要分两类： Codex 与 MemoHarness 共用 GPT-5.3-Codex ，分差更接近「只换 harness 」；厂商整包产品则模型、工具、权限绑在一起，只能读成「同一考场规则下，它公布的那套用法」好不好，不能当成拆掉 harness 后的纯模型对决。

三个源基准上，交付 harness 相对初始基线都有提升： Terminal-Bench 0.722→0.806 （+8.4 个百分点）， LiveCodeBench 0.900→0.967 （+6.7 个百分点）， FinanceAgent 0.600→0.767 （+16.7 个百分点）。涨幅最大的是 FinanceAgent ，基线留下的空间也最大； LiveCodeBench 已接近天花板，提升更小。

步骤多、失败方式也多的任务更吃 harness 搜索；接近满分的单次代码生成，搜索多半只在很小的分数区间里蹭一点。论文附录还做了「原子操作」层面的增益分析：哪些维度的哪类改动，更常跟着奖励上涨出现。这对理解「下一刀该改哪」比只看总分更有用。

换数据集、换模型：收益是选择性的。把各源基准上搜到的最终 harness 原样迁到六个未见过的评测套件，基座仍固定为 GPT-5.3-Codex ，对照同一套未调优的 Codex 基线。

专有 API 与开源权重模型都有收益，更像是搜到了「怎么取上下文、何时调工具、如何管中间状态、怎样收尾校验」这类流程习惯；若只是某模型私有提示口吻，换开源权重不该普遍上涨。 GPT-4.1 增益偏小，也符合「基座已经较稳时， harness 可改空间更窄」的判断，但仍需更大模型与任务集合确认。

成本：多出来的输入，大半进了缓存。在 Terminal-Bench 留出的 18 题正式评测集上，同一基座 GPT-5.3-Codex ，按公开标价事后核算美元成本。

经验检索会推高原始输入 token ；若线上缓存命中差、或提示几乎每题都变，＄ 6.89 这张账单就不好直接拿去对标。选型规则本身仍只把原始 token 当打平时的第二标准，不用美元，这和「训的时候尽量做对，费用事后另算」的设计一致。

边界与可借鉴处。MemoHarness 把执行经验当成可复用的 harness 基建：六维拆分让失败能指到具体维度，经验库让搜索带诊断，测试时再按题改编，部署就不必只剩一套全局配置。在本文评测规则下，相对对照的固定 harness 有提升；换套件、换模型时收益是选择性的；大量检索上下文能进缓存时，额外费用也可控。

论文自己留的口子同样清楚：统计稳健性、组件级归因、完全无监督搜索、更大规模验证，以及上线后持续累积经验，都还没做完。若线上仍是全站一套 harness ，先别急着上完整搜索。更划算的做法是：每次失败只标一个主因（检索、编排、校验），并按题型记下「改过什么、分数有没有涨」。攒够几十条这种记录，再评估要不要做 MemoHarness 式的按题改编。
