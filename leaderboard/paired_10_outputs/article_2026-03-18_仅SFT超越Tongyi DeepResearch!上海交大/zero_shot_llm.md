上海交通大学开源了完整的搜索 Agent 训练数据与模型。只用 11.7k 样本、做一次简单的 SFT，就在多个基准上超过了 DeepDive 等开源方案，甚至在中文基准上压过了阿里通义千问的 DeepResearch。

信息爆炸的今天，能不能从海量网页里又快又准地捞到需要的信息，已经成为决策的关键。而具备深度搜索能力的 LLM Agent，更是前沿模型的核心竞争力。可长久以来，高性能搜索 Agent 的研发一直是巨头的游戏——数据和算力都在他们手里，配方却捂得严严实实。这层看不见的数据壁垒，让大多数研究者很难真正参与进来。

现在，来自上海交通大学的纯学术团队给出了 OpenSeeker。

这是第一个完全开源的搜索 Agent：不仅放出了模型权重，还第一次把完整训练数据公开出来，里面包含复杂问答对和完整轨迹。仅靠 11.7k 合成样本、单次 SFT 训练，OpenSeeker 就在 BrowseComp、BrowseComp-ZH、xbench-DeepSearch、WideSearch 四个权威基准上拿到了开源 Agent 的最佳成绩；在中文基准上，它甚至超过了阿里通义千问的 DeepResearch。

**两项核心技术，撑起高质量数据**

OpenSeeker 的数据质量，来自两个关键突破。

**1. 基于事实的可扩展可控问答合成（Fact-grounded Scalable Controllable QA Synthesis）**

传统方法生成的问答往往太简单，模型靠关键词匹配就能答出来，根本练不出真正的多跳推理。团队换了一套全新的数据合成范式：

(1) 图扩展（Graph Expansion）：从大规模网页语料里随机采样种子页面，沿着出边遍历，构建局部依赖子图。

(2) 实体提取（Entity Extraction）：找出子图的中心主题，把关键实体抽出来，重构成结构化的实体子图。

(3) 问题生成（Question Generation）：按实体子图的结构出题，确保回答时必须遍历图里的多个节点。

(4) 实体模糊化（Entity Obfuscation）：把具体实体换成模糊的描述性指代，堵死模型靠关键词"抄近道"的路。

(5) 问题模糊化（Question Obfuscation）：把这些模糊实体再融进问题里，最终得到一个必须深入图结构遍历才能解开的难题。

整套流程保证了三个特性。事实锚定：问题来自真实网页拓扑，从根源上消除幻觉。可扩展性：TB 级网页档案都能拿来生成数据，几乎取之不尽。可控难度：调整子图大小 k，就能精确控制推理复杂度。整个流程是这样的——先从种子节点扩展成子图，提取关键实体构建实体子图，基于结构生成问题，最后通过实体模糊化加大难度。

**2. 去噪轨迹合成（Denoised Trajectory Synthesis）**

真实的网络搜索里，原始观察往往夹杂大量噪音和无关信息。怎么让模型从这些噪音里抓到关键信号？

(1) 动态上下文去噪：生成轨迹时用回顾式摘要。每次工具调用后，把原始响应压缩成"摘要响应"，替换掉历史窗口里的原始内容。

(2) 非对称训练：合成阶段用干净的去噪上下文（含摘要），训练阶段却用原始、未经处理的上下文。这种不对称逼着模型自己学会去噪和信息提取。

**实验结果**

主实验里，OpenSeeker 基于 Qwen3-30B-A3B 训练，四个基准上的表现如下：

| 模型 | BrowseComp | BrowseComp-ZH | xbench-DeepSearch | WideSearch |
|---|---|---|---|---|
| OpenSeeker | 29.5% | 48.4% | 74.0% | 59.4% |
| DeepDive-32B | 15.3% | 29.7% | 51.8% | - |
| Tongyi DeepResearch | 43.4% | 46.7% | 75.0% | - |
| WebSailor-V2-30B | 35.3% | 44.1% | 73.7% | - |

几个值得注意的点：只用了 11.7k 合成样本（10.3k 英文 + 1.4k 中文），简单 SFT 单次训练，没有任何超参数调优；BrowseComp 上几乎是把 DeepDive 甩了一倍（29.5% vs 15.3%）；BrowseComp-ZH 上超过了阿里通义千问 DeepResearch（48.4% vs 46.7%）。OpenSeeker 也是唯一一个在四个搜索基准上都具备竞争力的完全开源 Agent，而且靠的只是单次简单 SFT。

**消融实验**

团队分别验证了两项技术的贡献。

(1) QA 合成方法对比：相比直接拿网页语料生成问答，基于图结构生成的问题需要更多工具调用、更长的推理链，更贴近真实复杂搜索场景。英文数据难度对比上，OpenSeeker 的数据和 BrowseComp-EN 用同一个模型推理，复杂度相当。

(2) 去噪轨迹训练：用去噪轨迹训练出来的模型，在长序列任务上更稳，更擅长从带噪音的响应里提取关键信息。中文数据难度对比里，OpenSeeker 数据的平均 token 数和工具调用数明显高于 BrowseComp-ZH，说明数据更有挑战。

**技术方法详解**

问题形式上，团队把网络建模成有向图，表示网页，表示超链接，目标是合成问答对，使解决它需要长度为的轨迹。

为保证数据既难又可解，他们用了拒绝采样做双重过滤：

(1) 难度标准：让基础模型在闭卷设置下答题，答对了就丢掉——确保问题必须借助外部工具。

(2) 可解性标准：给模型提供完整的实体子图作为上下文，如果还是推不出正确答案——说明推理链断了，同样丢弃。

训练配置：基座模型 Qwen3-30B-A3B-Thinking-2507；参数规模总共 30B，推理时激活 3B；最大工具调用次数 200；上下文窗口 256k；训练样本量 11.7k（10.3k 英文 + 1.4k 中文）；训练方式为单次 SFT，不做数据过滤，也不调超参。

**局限性与未来工作**

当前工作还有不少限制。资源上，算力有限，BrowseComp 只在 200 个样本的子集上做了评估。训练只做了一次，没做迭代优化或超参搜索，还有提升空间。数据规模上，目前只用了约 68GB 英文和 9GB 中文网页数据，TB 级网页档案还没开发。接下来，团队打算做更大规模的数据合成、多语言扩展、更复杂的推理任务，以及强化学习后训练优化。

**总结**

OpenSeeker 说明了一件事：就算没有巨头的算力和数据优势，靠策略性的数据合成，一样能弥合和工业级成果之间的性能差距。把训练数据完整开源，等于给社区提供了一份透明、可复现的"配方"，让更多研究者能参与进自主 Agent 的研发。

这是第一份由纯学术团队完成、在前沿搜索基准上做到最先进水平、同时完整公开训练数据的工作。团队希望 OpenSeeker 能推动一个更开放、更协作、也更健康的 Agent 研发生态。

在 OpenSeeker 之前，高性能搜索 Agent 的训练数据一直是个"黑盒"。就连 DeepDive 这样的开源方案，也从没公开过自己数据的构建方法。结果是，广大研究者没法做这几件事：复现前沿结果——没有训练数据，方法是否有效就无从验证；进行公平对比——不同方法用的数据差异太大，难以做科学的对照实验；推动领域进步——创新往往建立在开源社区的集体智慧上，而数据壁垒严重拖慢了这一步。OpenSeeker 的发布，彻底改变了这种局面。

11.7k 样本规模不大，但数据构建流程完全透明，每个研究者都能据此理解高质量搜索 Agent 数据的核心设计原则，在此基础上改进和创新，训练自己的搜索 Agent，用于学术研究或应用开发。

**怎么用 OpenSeeker？**

对研究者来说，OpenSeeker 提供了一整套训练 pipeline：用数据集——从 HuggingFace 下载 OpenSeeker-v1-Data，里面是经过严格筛选的高质量问答对和轨迹数据；微调模型——用提供的 SFT 配置对 Qwen3-30B-A3B 做微调；评估对比——在 BrowseComp 等基准上测模型表现。团队在 GitHub 仓库里准备了详细文档和示例代码，新手也能很快上手。
