训练一个购物 Agent ，最尴尬的地方不在失败本身，而在于你只知道它最后买错了，却不知道它是搜错词、点错商品，还是最后尺码没选对。

长程 Agent 经常遇到这个问题。它要先搜索商品，再核对颜色、尺寸、价格，最后点击购买。环境通常只给一个最终结果，很少告诉模型中间哪一步该保留、哪一步该改掉。

SEED 这篇论文抓住的就是这个训练缺口。最终奖励太粗， Agent 的每一步动作却很细。论文的做法是：让模型在训练时先看完自己的一整条轨迹，写出一条可复用的事后复盘规则，再把这条规则对原动作的影响蒸馏回模型参数里。这里的“复盘规则”对应论文里的 hindsight skill ，可以理解成模型看完整条轨迹后写下的简短经验。

论文给出的整体结果。 SEED 在 ALFWorld 、 Search-based QA 和 WebShop 三类长程任务上都拿到最高平均表现。

这里的复盘规则只在训练时出现，作用更像一段带有经验总结的临时老师，并不会在部署时额外塞进模型提示词。训练结束后， Agent 推理时仍然只看普通任务上下文，不需要技能库、检索模块或额外提示。

这点很关键。很多反思类 Agent 方法会把历史经验存在外部记忆里，推理时再取出来用。 SEED 走的是另一条路：把经验对行为的影响写进参数，让模型下次在类似状态下自然提高正确动作的概率。

这会带来两种浪费。

失败轨迹里可能有正确片段。 Agent 可能已经找到目标商品，只是最后选错颜色；或者已经查到关键证据，只是在合成答案时漏了一跳。单个失败奖励会把这些有用行为一起压低。

成功轨迹里也可能有低效片段。 Agent 最后答对了，但中间多搜了几次、绕了远路、点了无关页面。最终奖励无法告诉模型这些动作其实不值得保留。

SEED 的出发点是：任务结束后，完整轨迹本身暴露了很多在线决策时看不到的信息。成功轨迹能总结出可复用流程，失败轨迹能总结出应避免的错误。问题是怎样把这种“事后复盘”变成模型能学习的信号。

方法：先复盘，再蒸馏

SEED 分成两个阶段。

第一阶段是复盘规则监督微调。研究团队先用基础策略收集离线轨迹，每个任务采样多条完整交互记录。然后用外部分析器读取轨迹，生成自然语言技能。成功轨迹的技能偏向“流程”，失败轨迹的技能偏向“避错规则”。这些轨迹与技能配对后，用来微调模型，让它具备读取完整轨迹并写出复盘技能的能力。

第二阶段才是核心：持续用新轨迹做在线蒸馏，论文称为自演化 OPD 。每轮训练开始时，先把当前模型复制一份固定住。这个固定模型既负责去环境里跑任务，也负责看完轨迹后写复盘规则。

SEED 的两阶段流程。第一阶段教模型复盘轨迹；第二阶段让最新策略同时负责采样和复盘，再把技能带来的行为变化蒸馏回普通策略。

这样做有一个好处：负责复盘的模型不会长期停留在旧水平。策略变强后，它遇到的状态、犯的错、能总结出的规则都会变。 SEED 每轮都用最新 checkpoint 做分析器，让“会做任务”和“会复盘任务”一起更新。

接下来是蒸馏部分。可以把这一步理解成一次事后阅卷：同一个已经发生的动作，先按原始上下文打一次分，再把复盘规则塞进去重打一遍分，看规则到底是支持它还是反对它。

SEED 最终同时优化两项：一项是环境最终奖励驱动的 GRPO 损失，另一项是技能蒸馏带来的逐 token 损失。

这套设计最值得注意的地方，是它没有替换强化学习。最终成败奖励仍然决定任务方向，复盘规则负责补上中间动作的细粒度信用分配。

复盘规则长什么样

论文里的复盘规则面向策略，不写成长篇解释。

轨迹分析器生成的复盘规则示例。成功轨迹总结流程，失败轨迹总结避错规则。

在 ALFWorld 里，成功规则会写成：清洗并放置物体时，先找到目标物，再带到清洗点清洗，最后移到目标位置。失败技能则提醒：不要在确认物体已拿到、状态已满足前就移动到目标位置。

在 WebShop 里，成功规则强调结构化搜索、核对商品类别、选择颜色和尺寸后再购买。失败技能会提醒模型不要点击无关结果，不要购买只满足部分条件的商品。

这些规则本身并不神秘。它们像人做任务后的复盘笔记。 SEED 的价值在于把这些总结转成训练时每个动作 token 的概率偏移。普通策略学到的是行为倾向，推理时不需要再多读一段提示词。

主结果：三类长任务都提升

论文在三类典型 Agent 任务上测试 SEED 。

ALFWorld 是文本版家庭任务， Agent 要根据观察执行一串动作，比如找物体、清洗、加热、放置。 WebShop 是网页购物任务， Agent 要搜索商品、核对属性并购买。 Search-based QA 要先搜索证据，再回答问题，覆盖 Natural Questions 、 TriviaQA 、 HotpotQA 等多个问答集。

主表比较了 Qwen2.5-3B 、 Qwen2.5-7B 和 Qwen3-1.7B 三个底座模型，以及 Vanilla 、 Skill-Prompt 、 GRPO 、 Skill-GRPO 、 OPSD 、 Skill-SD 、 RLSD 、 SDAR 等基线。

主结果表。 SEED 在三个底座模型、三类任务上多数聚合指标领先，尤其在 ALFWorld 和 WebShop 成功率上优势明显。

几个数字最能说明问题。

在 Qwen2.5-3B 上， SEED 的 ALFWorld 平均成功率达到 91.8%， GRPO 是 75.0%； WebShop 成功率达到 78.9%， GRPO 是 63.3%。 Search-based QA 的平均准确率从 GRPO 的 36.4% 提到 45.7%。

在 Qwen2.5-7B 上， SEED 的 ALFWorld 平均成功率是 96.1%， GRPO 是 81.2%； WebShop 分数 89.7 ，成功率 78.1%。

在更小的 Qwen3-1.7B 上， SEED 的提升更明显： ALFWorld 平均从 GRPO 的 46.1% 提到 92.0%， WebShop 成功率从 38.3% 提到 77.3%。小模型的提升尤其值得看，因为它本来更难从稀疏奖励里摸到正确路径。 SEED 在这里拉开差距，说明复盘信号确实缓解了信用分配问题。

另一个对照也很有意思。 Skill-Prompt 是在测试时直接给模型技能提示， Skill-GRPO

 也是测试时保留技能上下文。 SEED 推理时不提供技能，却在 12 个聚合比较里有 11 个超过 Skill-GRPO

。至少在这些任务上，把技能写进参数，比临时塞提示更有效。

学得更快，也更会迁移

如果只看最终分数，还不能说明 SEED 是否只是多花训练成本换来的结果。论文进一步看了训练过程和样本效率。

ALFWorld 训练曲线。 SEED 在较早阶段就和 GRPO 拉开成功率差距，同时平均交互步数下降更快。

在 ALFWorld 上，训练到第 40 步左右时， SEED 成功率约 57%， GRPO 约 35%。到训练后期， SEED 的平均交互长度从约 28 步降到约 13 步， GRPO 最后约 16 步。由于成功率同时上升，论文把这种步数下降解释为更快找到有效路径，而不是提前结束。

样本效率的结果更直接。

样本效率对比。 SEED 用 60% 的 ALFWorld 训练数据达到 80.7 ，超过 GRPO 使用全部数据的 75.0 。

在 ALFWorld 上， SEED 只用 60% 训练数据就达到 80.7 ，超过 GRPO 满数据的 75.0 。用 40% 数据时， SEED 为 58.9 ，接近 GRPO 用 80% 数据的 58.6 。 WebShop 上也类似， SEED 在不同数据比例下都超过 GRPO ，满数据时成功率优势达到 15.6 个点。

SEED 的收益不是简单堆训练步数。它更像是把一条轨迹从“只有最终对错”，拆成了多个可学习的局部信号。

论文还测了 ALFWorld 的 unseen split ，也就是没在训练环境里见过的任务组合。

ALFWorld 未见环境上的泛化结果。 SEED 平均成功率从 GRPO 的 70.9 提到 86.2 。

SEED 平均成功率从 GRPO 的 70.9 提到 86.2 ，提升 15.3 个点。六类任务里有五类提升，其中 Heat 提升 35.0 个点， Look 提升 18.3 个点， Pick 提升 16.5 个点。 Clean 下降 2.9 个点，是表里唯一没有提升的类别。

这个结果支持论文的一个判断： SEED 学到的不只是训练轨迹本身，还包括可迁移的行为规则，比如先找目标、确认状态、处理前置条件、保留任务约束。

哪个组件最关键

消融实验拆掉了 SEED 的三个核心组件：事后技能监督微调、自演化 OPD 、来自当前模型刚跑出的轨迹。

消融结果。去掉来自当前模型刚跑出的轨迹损失最大，说明复盘最好来自当前模型刚跑出的轨迹。

完整 SEED 在 ALFWorld 上平均 91.8%。去掉事后技能监督微调后降到 86.0 ，说明模型先学会“读完整轨迹并总结技能”是有帮助的。

去掉自演化 OPD 后降到 87.0 。只在第一阶段学一次复盘能力还不够，训练中持续把新轨迹转成新监督才是关键。

损失最大的是把在线技能换成静态离线技能库，平均降到 84.4 。原因也直观：策略训练过程中会不断改变。早期会犯的错，后期可能已经修好；后期遇到的新状态，旧技能库又覆盖不到。来自当前模型刚跑出的轨迹，才更贴近它正在经历的失败模式。

一个案例：少走弯路

论文给了一个 ALFWorld 案例：任务是把蜡烛放进厕所。

定性案例。 GRPO 训练的 Agent 先去目标位置、拿了无关厕纸，之后在无效位置间循环； SEED 训练的 Agent 先查可能存放蜡烛的架子，找到后完成放置。

GRPO 训练的 Agent 一开始先去厕所看，后来还拿了厕纸，随后在厕所、架子、水槽、厕纸架之间循环，没有找到也没有拿起蜡烛。

SEED 训练的 Agent 则先判断蜡烛可能在架子或柜子上，依次检查 shelf 1 、 shelf 2 ，在第二个架子上找到蜡烛，再移动到厕所完成放置。

这个例子对应前面的机制：失败轨迹会生成“不要在没确认目标物和状态前就移动或放置”的避错规则；成功轨迹会生成“先找目标物，再执行目标动作”的流程。训练时这些规则不直接出现在测试上下文里，但模型的动作概率已经被调过。

视觉任务也能用

SEED 还做了一个多模态扩展，用 Qwen2.5-VL-3B-Instruct 测 Sokoban 和 EZPoints 。

Sokoban 是 6×6 视觉网格推箱子，错误推动可能造成不可逆死局。 EZPoints 要识别两张牌并逐步构造等于 12 的表达式。它们都要求视觉状态跟踪和多步规划。

Sokoban 轨迹示例。模型需要根据视觉网格连续选择移动方向，避免把箱子推入死局。

结果上， SEED 在 Sokoban 成功率 82.0%， GRPO 为 67.1%； EZPoints 成功率 100.0%， GRPO 为 86.9%；两个任务平均从 77.0% 提到 91.0%。

这部分实验规模不算大，但说明 SEED 的想法不限于纯文本。只要轨迹能被序列化成“任务、观察、动作、结果”，分析器就有机会从完成后的过程里提取事后技能。

边界：自我复盘也会继承盲点

SEED 的好处很清楚：训练时多了更细的过程监督信号，推理时不增加额外模块。它适合那些终局奖励容易拿到、过程监督难标注的 Agent 任务。

但它也有两个实际边界。

第一，复盘来自模型自己，可能继承模型盲点。论文在讨论里也提到， actor 和 analyzer 共享同一个策略，能力提升会一起传递，错误偏好也可能一起传递。如果分析器把某个反复出现的错误总结成“可复用规则”，后续训练就可能强化这个错误。

SEED 用在线轨迹和门控减少噪声，但门控只表示“技能增强上下文让这个 token 概率变高”，不等于语义上一定正确。更稳的版本可能需要让复盘规则必须对应到环境里真的发生了什么，比如物体是否拿到、页面是否跳转、答案证据是否找到，或者比较不同 checkpoint 的分析结果。

第二，训练成本会上升。 SEED 推理时没有额外开销，但训练成本主要多在两处：每条轨迹要额外生成一次复盘规则；同一批动作还要在普通上下文和规则增强上下文各跑一遍打分。上下文越长、图片越多、工具调用越复杂，这部分开销越容易变成瓶颈。

论文当前的实验覆盖 ALFWorld 、 WebShop 、 Search-based QA 、 Sokoban 和 EZPoints ，已经横跨文本、网页、搜索和视觉规划。但更长、更开放的真实 Agent 环境里，事后技能能否持续准确，仍然需要更多验证。

我觉得这篇工作的价值在于，它把“Agent 复盘”从推理时的提示工程，推进到了训练目标设计里。复盘不再停留在多写一段总结，而会变成普通策略可吸收的概率信号。

如果长程 Agent 训练继续依赖最终成败奖励，这类把完整轨迹重新拆成局部监督的方法，会越来越重要。
