一句话讲清楚👉🏻

 阿里 Qwen 大模型应用团队开源 Skill Self-Play （ Skill-SP ）：用会进化的 skill 库同时管「出什么题」和「怎么自动判对错」，让自博弈既能覆盖开放任务，又能挡住假题；工具调用最高抬 42.9 分，逻辑推理上也能把几乎起不来的弱模型拉回正轨。

论文标题：

Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills

做工具调用自博弈时，很多人会卡在同一件事。接上代码执行器或游戏模拟器，反馈很干净，但场景出不去，模型只会在窄环境里变强。放开让模型自己出题，任务面宽了，题却经常格式像样、其实练了也不涨分；事后过滤只能挡明显坏题，挡不住这类「看起来合法、不可学」的样本。噪声进环以后，越迭代越塌。

Skill-SP 想同时保住这两头。它把 agent skill 当成训练期的题型插件：能被路由选中，自带校验，还能随失败案例改写。每个 skill 管一类可深挖、可自动验的场景；多个 skill 来回切换，任务种类才撑得开。这和推理时临时检索一段提示是不同用法： skill 在这里是出题与验题的共享接口。

Figure 1 ：左是绑死外部环境（可验证但覆盖窄）；中是开放出题再事后过滤（宽但易留残差）；右是 Skill-SP ，用主动 skill 编排同时保覆盖与题质量。

在 Qwen3-4B-Instruct 上， Skill-SP 相对基座把工具调用与逻辑推理多个维度一起抬上去。无引导自博弈在逻辑侧甚至合不成有效谜题，雷达图上直接缺席。

Figure 2 ： Qwen3-4B-Ins 上三条曲线的对比。无引导方法在逻辑谜题上起不了有效训练环。

三个角色怎么转起来

Skill-SP 拆成三个角色：出题的 proposer 、做题的 solver 、管 skill 库的 controller 。每一轮先记三步：挑题型出题，拦假题，只留「大概半对半错」的题进训练池。后面的策略更新，以及 skill 的改写、归档与新增，都围着这批题转。

Figure 3 ：总览。有效性校验在前，前沿筛选在后；库的精炼、剪枝、诱导跟在执行反馈后面。

只奖励「成功率接近 0.5 」很容易被钻空子： proposer 故意出病态题，把难度伪装成刚好一半。 Skill-SP 因此先过「这题能不能学」的门：格式乱、校验不过、参考对不上，直接零分。过门之后，才看成功率是不是卡在五五开附近：太易或太变态都接近零。

𝟙

外层让 skill 库与 proposer 一起产出「有效且卡在半对半错」的题；内层让 solver 在这些题上把执行成功率拉高。两边一起动，难度信号才不会过时。

skill 是一份出题说明书，还要留一条探索流

可以把一个 skill 想成一份出题说明书，里面固定有六块：怎么路由、有哪些硬规则、生成时用什么提示和例子、怎样自动判对错，以及这题型最近练得够不够。论文里写成 

，就是这六块的缩写。出题时按使用统计采样，在「高收益题型」和「测得不够的题型」之间做平衡。

生成有两条流。 skill 流：按采样到的说明书出题，结构先验强。探索流：不加 skill 约束，专门探新模式，避免整库塌进少数模板。消融里如果只保留 skill 流， API-Bank 上的跨场景表现会掉，说明探索流不是摆设。

有效性也不只看格式。 skill 流要同时满足：全局 schema 合规、 skill 自带校验器通过，以及「让当前 solver 多答几次」：多数答案唯一，且与出题方给的参考一致。后一条就是文中的探针一致性，用来挡「契约写了、模型却答不稳」的假题。探索流不做 skill 专属校验，但仍要过基础质量门。

库怎么跟着长：改、删、加

库一成不变，练的题型很快变太简单。每一轮三件事。

改：根据无效生成与执行轨迹，重写说明书内容，并更新使用统计，影响下一轮路由。删：长期太简单、前沿奖励过低的 skill 归档，把出题名额留给还卡得住模型的类型。加：从探索流里挑难度合适的新题，让 controller （初值也是基座）抽象成新 skill 包；再过完整性检查，以及相对旧库够不够新，才入库。

这样库会跟着训练一起变：旧题型被压成可复用说明书，新题型从开放探索里筛进来，不必把历史轨迹整段塞进出题 prompt 。

工具调用：五种骨干都涨， Ministral 涨幅最大

评测在 API-Bank （ L1–L3 ）和 BFCL （ JS / Python / Java / Live ）上报告 avg@8 （每题采 8 次取均）。对照是基座，以及去掉 skill 编排、只靠事后过滤的无引导自博弈。

Table 1 ：工具调用主结果。 Skill-SP 五行骨干全面正增益；无引导自博弈增益更小，个别子项还会掉。

能力本来就不错的骨干，涨幅偏稳： Qwen3-4B-Ins 总均分 +6.5 （ 60.2→66.7 ）， Qwen3-8B +2.8 ， Granite-4.1-3B +5.3 。无引导也有一点提升，但更小，且偶发子项回退。

总判断可以记成两句。强骨干： Skill-SP 稳抬天花板。弱骨干：它几乎是在补点火。 Ministral-3-8B 基座总均分只有 20.7 ，无引导几乎不动（+0.1 ）， Skill-SP 抬到 63.6 （+42.9 ）； Ministral-3-14B 从 22.2 到 64.5 （+42.3 ）。基座自己几乎合不成有效题时，无引导环缺少可用学习信号； skill 先把「什么叫有效任务」钉住，反馈才回得来。

逻辑推理：无引导起不了环， Skill-SP 能起

逻辑侧用 ZebraLogic （一类斑马谜题式的约束满足题），按搜索空间分成 Small / Medium / Large / X-Large ，报告整盘网格正确率与单元格正确率。复杂谜题对结构合法性要求极高，无引导经常直接塌掉，论文因此只在工具调用上报告无引导对照。

Table 2 ： ZebraLogic 主结果。五骨干网格正确率全升；弱模型在小盘上的绝对涨幅尤其大。

Qwen3-4B-Ins 网格正确率从 72.1 到 73.5 （+1.4 ）。 Qwen3-8B 从 23.6 到 32.4 （+8.8 ）。 Ministral-3-14B 从 5.4 到 17.4 （+12.0 ）， Small 盘从 14.9 跳到 50.2 （+35.3 ）；单元格正确率从 7.3 到 26.4 （+19.1 ）。 Ministral-3-8B 单元格正确率从 3.7 到 23.7 （+20.0 ）。

大盘仍难。一开始就很弱的模型，在 Large / X-Large 上进步有限。纯自博弈仍需要最低能力门槛； skill 能把门槛附近的题做对、做多样，但替不了「从零啃极大搜索空间」。 Qwen3-4B 的留出集轨迹也支持这一点：工具调用与逻辑两侧随迭代抬升更稳，逻辑侧无引导往往缺少可比曲线。

消融：去掉哪一块，掉的是什么

在 Qwen3-4B-Instruct 上，论文拆了「数据怎么组」和「两边策略是否一起更新」两组。

Figure 4a ：学习轨迹。 Skill-SP 抬升更稳；无引导更早平台，整体低 2.6 分。

Figure 4b ：只用 skill 流组池， API-Bank 跨场景表现掉下来；双流混合才保住多样性。

Table 3 ：数据环消融。相对完整系统，无引导 -2.6 ，均匀路由 -1.9 ，冻结 skill 库 -2.3 。

无引导缺主动结构引导，复杂任务上不够用。只吃 skill 流会过专化。均匀路由与冻结 skill 也都更差。增益来自动态分配与库持续进化，单靠塞几段静态说明不够。

Table 4 ：更新环消融。冻结出题器 -2.1 ；冻结给难度打分的 feedback solver -3.0 ；两边都冻 -3.2 。

这里的 feedback solver ，可以理解成专门给难度打分的做题副本：负责探针和估 

，可以和最终上线的 solver 同源。消融里把它冻住，等于给 proposer 喂过时难度。出题策略要会用进化中的库；估难度的那一侧也要跟着走。两边一起冻，掉得最狠。

过程诊断：题是不是真卡在半对半错

终局分数看不清过程。论文用 Qwen3-4B 工具调用自博弈做了三张诊断图。

Figure 5a ： skill 流接受样本的平均成功率约 0.57 ，更贴「半对半错」；无引导与探索流分别漂到约 0.70 与 0.75 。

Figure 5b ：把题目嵌进向量再做主成分投影。无引导题挤在窄语义区； Skill-SP 混合池更散。

Figure 5c ：五轮里每轮大约新增 20 个 skill 包，同时持续改写与退役旧包。

Figure 6 ：五轮后活跃 skill 约 86 ；按使用分布的熵估算「真正被较均匀用到」的有效 skill 约 46 ，扩库没有变成少数题型刷屏。

若把 skill 理解成换皮过滤，这组诊断对不上。 skill 流在把难度钉在半对半错附近，诱导在扩覆盖，利用率则表明课程没有塌成少数模板。

边界，以及打开仓库可以先看什么

Skill-SP 换来的是：出题有规矩、对错能验、库还能跟着长。代价是要维护这套会更新的说明书，并且领域仍得写成机器可读契约：工具调用的 schema 与探针、逻辑谜题的确定性检查器，都是前提。契约写不出来的开放 Agent 任务，这篇没有给出答案。

结果里的边界也清楚。几乎产不出有效题的模型，无引导会空转， skill 编排价值最大；已经较强的骨干，涨幅更像稳抬天花板。极大搜索空间上，弱模型仍缺最低信号门槛。只留 skill 流会伤多样性。主实验停在 5 轮、 3B–14B 、两族可验证任务；更长迭代与外挂更强教师未覆盖。

代码已开源。若你也在跑同类自博弈，终局均分之外不妨先盯三件事：有效题比例是否随轮次上升、训练池里成功率是否长期贴在 0.4–0.6 、活跃 skill 是否在扩而不是少数模板霸榜。这三项比只看最后一张表，更容易判断环有没有在空转。
