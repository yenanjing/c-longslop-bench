LLM的"健忘症"：一个绕不过去的坎

过去几年大语言模型的能力飞速扩张，数学推理、代码编写、多轮对话，一个接一个的难题被攻克了。但有一个问题到现在都没真正解决：

长期记忆

。

认知科学的研究表明，人类长期记忆的功能性信息容量大约在 

 比特量级。按照每个Token约33到55比特的有效语义密度换算，这相当于人的一生大约能积累2到3亿Token的信息量。

然而现在主流LLM的有效上下文窗口大多被限制在128K到1M Token之间。即便Qwen2.5-14B-1M、Qwen3-30B/80B-A3B这些专门做了长上下文训练的模型，也几乎没人能真正突破1M的门槛。也就是说，模型记忆和人类记忆之间差了

两到三个数量级

。

这个鸿沟为什么这么难跨？根子在Full Attention架构的二次方复杂度——上下文越长，计算量平方增长。光堆算力不行，得从架构上找新路子。

现有的解决方案大致分为三类，各有各的痛点：

参数型记忆

（如LoRA、持续预训练、Titans）：直接将知识注入模型参数，精度高但容量有限，而且容易发生灾难性遗忘，管理起来也很麻烦。

外部存储型记忆

（如RAG、MemAgent）：从外部数据库检索信息，容量大且易管理，但检索过程不可端到端优化，精度有天花板，本质上还是"检索完再读"的解耦范式。

隐状态型记忆

（如RWKV、DeltaNet）：将历史压缩到固定大小的隐状态中，计算效率高但有损压缩严重，上下文一长就出现灾难性退化。

这三类方法都无法同时满足高精度、终身级容量、端到端可训练和线性复杂度这四个核心需求。

MSA：一个优雅的解法

盛大集团旗下的Evermind团队发了一篇论文，提出了

Memory Sparse Attention（MSA）

——一套端到端可训练、高效且极度可扩展的记忆模型框架。核心思路是把

记忆容量和推理能力拆开

。

MSA基于Qwen3-4B-Instruct-2507骨干模型构建，在158.95B Token的去重语料上做持续预训练。4B参数的模型，2张A800 GPU，就能处理1亿Token的超长上下文，从16K扩展到1亿Token性能衰减不到9%。

这不是简单的工程修补，而是从架构、训练到推理引擎的全链路重新设计。

MSA在MS MARCO数据集上展现出惊人的可扩展性，从16K到1亿Token，性能衰减不到9%。相比之下，传统长上下文模型和外部记忆系统在极端尺度下出现灾难性退化。

核心技术二：文档级RoPE与全局RoPE混合策略

在扩展记忆规模时，一个关键挑战是训练和推理上下文之间的位置编码不一致。标准的全局位置编码会在拼接序列上分配单调递增的位置ID。当文档数量急剧增长时，位置索引会大幅偏移，导致推理上下文长度超过训练范围时出现严重退化。

MSA的解决方案是

为每个文档分配独立的位置ID（从0开始）

。这种文档级RoPE策略将位置语义与记忆库中文档的总数脱耦合，使模型只需在较小的文档子集上训练，就能有效外推到超大规模记忆库。

同时，MSA对活跃上下文（用户查询和自回归生成部分）使用全局RoPE。查询的位置ID从k开始偏移（对应Top-k个检索到的压缩KV），确保模型将活跃上下文感知为检索到的背景信息的逻辑延续，保持因果依赖关系。

这种"短训练、长推理"的设计，让MSA只需在64K上下文上训练，就能有效外推到1亿Token，大幅降低了训练开销。

核心技术三：三阶段推理与Memory Parallel

MSA的推理流程分为三个阶段，从编码到检索再到生成，形成一个完整的闭环。

阶段一：全局记忆编码（离线）

这是一个一次性的离线预计算过程。对语料库中的每个文档，模型执行前向传播生成标准的K和V矩阵，同时Router K Projector生成路由键矩阵 

。所有矩阵通过分块均值池化压缩后缓存到记忆库中。这一步将原始文本语料转化为结构化的、可检索的隐状态存储。

阶段二：路由与上下文组装（在线）

收到用户问题后，模型计算问题的隐状态并通过Router Q Projector得到路由查询 

。用这个查询去匹配缓存的全局路由键 

，计算相关性分数并选出Top-k个文档。然后只加载这些被选中文档的压缩Key和Value矩阵，与问题的本地 

、

 拼接，形成最终的稀疏上下文。

阶段三：稀疏生成（在线）

模型在组装好的稀疏上下文上执行自回归生成，逐Token产生最终答案。

然而，要在实际硬件上实现1亿Token的推理，还面临着巨大的工程挑战。论文给出了一个估算：假设池化核大小 

，8个注意力头，头维度128，18层BF16精度，1亿Token的压缩KV和 

 缓存大约需要169GB内存，这已经超过了2张A800 GPU总共160GB的显存容量。

MSA的解决方案是

Memory Parallel推理引擎

，包含两个关键优化：

分层存储策略

：观察到检索只需要路由键 

，而内容 

 和 

 只在选择后才需要。因此，将路由键驻留在GPU显存中（分布式存储在多张GPU上），而将大量内容KV卸载到CPU内存（主机DRAM）中。GPU完成Top-k评分后，仅异步从CPU加载被选中的内容KV。这种分离策略将容量需求与显存限制脱耦合。

分布式评分

：在多张GPU上复制完整模型权重以避免解码时的通信开销。查询隐状态被广播到所有GPU，每张GPU独立计算与其本地路由键分片的相似度分数，然后全局归约找出Top-k索引。评分矩阵乘法还实现了分块机制来管理峰值显存，防止OOM。

这套工程方案使得仅用2张A800 GPU就能处理1亿Token的推理。

核心技术四：Memory Interleave——多跳推理的关键

单次检索对于简单问题已经足够，但复杂查询往往需要多步推理，证据分散在记忆库的不同角落。MSA引入了

Memory Interleave（记忆交错）机制

来解决这个问题。

与一次性检索不同，Memory Interleave执行的是一个迭代过程：模型首先根据原始查询自回归生成一系列文档ID（以特殊分隔符结尾），然后系统获取对应文档的原始文本并追加到原始查询中。这个"生成证据标识符 -> 检索全局上下文 -> 更新状态"的循环会自适应地重复，直到模型判断已收集到足够证据，此时模型从生成文档ID切换为自回归生成最终答案。

关键设计在于，每轮生成的文档数量不是固定的，而是由模型自适应决定的。在训练时，多跳数据集中的每条检索链被拆分为多个训练样本，每个样本包含单次检索步骤（基于单一查询或已有文档上下文），然后随机采样训练。

包含Memory Interleave的三阶段推理过程。模型在"生成文档ID -> 检索原文 -> 扩展上下文"之间迭代，直到收集到足够证据后生成最终答案。

实验结果：一个4B模型能有多强

论文在9个QA基准和NIAH基准上做了系统测试。

QA任务：同骨架碾压RAG

在与相同Qwen3-4B-Instruct骨架的RAG系统对比中，MSA在9个数据集中的8个上取得了SOTA表现，平均提升幅度分别达到16.0%（vs 标准RAG）、11.5%（vs RAG+重排序）和14.8%（vs HippoRAG2）。

以MS MARCO v1（7.34M Token记忆库）为例，标准RAG的最优分数约为3.0，而MSA达到4.141——这是一个巨大的差距。即便面对使用KaLMv2-Embedding加Qwen3-235B或Llama-3.3-70B等前沿大模型的"最佳组合"RAG系统，MSA仍然在4个数据集上取得最优，平均分数达到3.760，相对提升5%到10%。

消融实验：拆掉哪个会崩

做了四组消融，一个个拆开看效果：

课程学习的影响

：移除第二阶段课程训练（S2 vs S1），平均性能下降7.6%。在拥有7.34M Token记忆库的MS MARCO上，S2比S1获得了高达29.5%的提升。渐进式地接触更长上下文对模型外推能力至关重要。

Memory Interleave的影响

：移除记忆交错机制后平均性能下降5.3%，HotpotQA（多跳数据集）下降19.2%。模型需要基于已获取证据迭代精化检索查询，才能完成需要证据链的组合推理。

持续预训练的影响

：移除CPT后平均性能暴跌31.3%。CPT包含的热身阶段能快速校准Router，大幅提升路由精度。多跳数据集HotpotQA下降43.1%，因为初始检索中的错误会在后续步骤中累积放大。

原始文本注入的影响

：移除原始文档文本后平均性能下降37.1%，是最严重的退化。DuReader下降46.2%。这说明虽然文档ID生成能有效定位相关证据，但后续注入原始文档语义对于提取精细事实细节仍然不可或缺。

MSA意味着什么

MSA的价值不只是发了一个厉害的长上下文模型。它提供了一套经过验证的技术路线，证明可扩展性、精度和效率三者可以兼得。

它表明，我们不必在RAG的"精度有限"和Full Attention的"算力爆炸"之间二选一。把稀疏化和端到端学习结合起来，搭一个独立的"记忆层"（Memory Layer）去兼容现有LLM，这条路走得通。

具体到应用场景，MSA至少解锁了几个之前做不了的事：

大规模语料摘要

：一次处理整本小说、整个代码库或完整的法律案卷

数字孪生（Digital Twins）

：在多轮对话中保持一致的人格和历史记忆

长历史Agent推理

：Agent系统能够追溯完整的交互历史并做出连贯决策

终身级个人助手

：记住用户的所有偏好、历史和上下文

这些都是当前1M Token窗口力所不及的场景。
