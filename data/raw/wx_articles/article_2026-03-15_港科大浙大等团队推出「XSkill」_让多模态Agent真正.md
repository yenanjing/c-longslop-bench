一句话讲清楚👉🏻 香港科技大学、浙江大学和华中科技大学联合团队提出的XSkill框架,通过双流设计(技能流+经验流)让多模态智能体能够从过往轨迹中持续学习,在不更新模型参数的情况下显著提升工具使用效率和编排灵活性。

为什么需要这项研究?

多模态大语言模型(MLLMs)的发展让智能体从被动的感知系统转变为主动的问题解决者,能够使用各种工具(代码执行、网络搜索、图像处理等)来完成复杂的推理任务。然而,现有的多模态智能体在实际应用中仍面临两个核心瓶颈:

工具使用效率低下

: 简单问题花费过多步骤,复杂问题却探索不足。比如,一个简单的图像识别任务可能需要多轮尝试才能找到正确方法,而复杂的多模态推理任务又缺乏足够深入的探索。

工具编排不灵活

: 大多数系统局限于单路径执行,难以将工具组合起来跨任务泛化。当遇到新任务时,智能体无法复用之前积累的经验,每次都要从头开始探索。

更关键的是,现有的持续学习方法主要依赖文本轨迹日志进行知识提取和检索,这在多模态场景中是远远不够的。因为在多模态任务中,关键的决策信号往往来自视觉观察,而非文本描述。比如,识别图像中的物体位置、判断图像是否需要旋转、发现小物体需要裁剪等,这些信息都蕴含在视觉内容中,纯文本日志无法有效捕捉。

那么,如何让多模态智能体在不更新参数的情况下,像人类一样从过往经验中学习,做到"举一反三"?这就是XSkill要解决的核心问题。

核心贡献

XSkill的创新在于把知识分成两层:

任务级的技能(Skills)

: 提供工作流和工具模板,告诉智能体"怎么编排工具"。比如"多物体检测"技能会包含:先分析图像特征,再决定是否需要预处理,然后用检测工具,最后验证结果。

动作级的经验(Experiences)

: 捕捉上下文相关的战术提示,告诉智能体"什么时候用什么工具"。比如"图像中出现小物体时,直接检测容易失败,应该先裁剪放大感兴趣区域"。

这两个层次不是简单的拼凑,而是各司其职又相互配合。技能解决"做什么"和"为什么做",经验解决"何时做"和"怎么做"。

另一个重要改进是让知识提取和检索都基于视觉观察。传统方法只看文本轨迹日志,XSkill会把视觉内容也纳入知识的组成部分。检索时根据视觉相似度匹配,适配时根据当前视觉内容重写知识。

整个流程构成一个持续学习循环:从轨迹中积累知识 → 推理时使用知识 → 使用历史反馈到知识库。在4个骨干模型上平均提升2.58-6.71个百分点,最好情况下提升了11.13个百分点。

XSkill框架概览:Phase I(左)从多路径轨迹中提取技能和经验,Phase II(右)检索并适配知识用于推理

两阶段架构

XSkill的工作流程分为两个阶段:

Phase I: 知识积累

给定训练数据集 

,智能体执行多路径探索(multi-path rollouts),通过以下步骤提取知识:

轨迹总结 (Rollout Summary)

: 对每条轨迹进行视觉定位的总结,将视觉观察和文本推理结合起来

跨轨迹批评 (Cross-Rollout Critique)

: 比较不同轨迹的成功与失败,提炼出关键经验

层次化整合 (Hierarchical Consolidation)

: 消除语义冗余,保持知识的质量和多样性

Phase II: 知识推理

对于测试任务 

,系统执行以下流程:

任务分解

: 将复杂查询拆分为子任务

知识检索

: 通过语义相似度检索相关的技能和经验

上下文适配

: 根据当前视觉上下文重写知识,使其更贴合具体场景

提示注入

: 将适配后的知识注入到智能体的系统提示中

视觉定位的关键作用

XSkill与传统方法的根本区别在于视觉定位(Visual Grounding):

传统方法的问题

:

仅依赖文本轨迹日志

无法捕捉视觉决策信号

检索到的知识可能与当前视觉上下文不匹配

XSkill的解决方案

:

提取时:结合视觉观察和文本推理

检索时:根据视觉相似度匹配

适配时:根据当前视觉内容重写知识

这使得智能体能够真正理解"什么时候该做什么",而不仅仅是记住"做了什么"。

深度解读

为什么双流设计有效

XSkill的双流设计不是简单的"两种知识拼在一起",而是对人类学习方式的模仿:

技能流像战略层,负责"做什么"和"为什么做"——提供高层次的执行蓝图,定义工具编排的标准流程,支持跨任务的抽象。

经验流像战术层,负责"何时做"和"怎么做"——捕捉上下文相关的细微洞察,提供失败模式的教训,填补通用流程和具体场景之间的空白。

两者分工明确:技能流提供框架,经验流提供细节;技能流确保正确性,经验流提升效率;技能流支持泛化,经验流确保适配。

视觉定位的价值

XSkill和传统方法的根本区别在于对视觉内容的处理:

传统方法只看文本日志,但多模态任务的关键决策信号往往来自视觉。比如识别图像中的物体位置、判断是否需要旋转、发现小物体需要裁剪——这些信息都在视觉内容里,文本日志很难捕捉。

XSkill的做法是:

提取时:把视觉观察作为知识的一部分

检索时:用视觉相似度匹配

适配时:根据当前视觉内容重写知识

这让智能体能真正理解"这个经验适用于当前场景",而不是机械套用文本描述。

持续学习循环的潜力

虽然论文中展示了单次积累-测试循环,但XSkill的架构设计支持真正的持续学习:

初始积累

: 从训练任务中提取知识

应用推理

: 在测试任务中使用知识

反馈优化

: 将使用历史回传,更新知识库

迭代改进

: 随着时间推移,知识库越来越丰富和精确

这种设计为未来的长期学习智能体提供了可能。

与大模型能力演进的配合

XSkill还有一个有意思的特性:知识可以跨模型迁移。

论文中的实验显示,Gemini-3-Flash积累的知识可以被Gemini-2.5-Pro使用。这意味着新模型不必从零开始学习,可以继承和优化前代模型的知识。

整个智能体系的能力可以累积增长。

局限性与未来展望

论文展示了单次积累-测试循环,持续迭代学习的效果还有待验证。多路径探索的计算成本较高,知识库的管理和更新策略也需要进一步优化。

未来的方向包括:实现真正的在线持续学习,支持动态知识库更新;开发更高效的知识表示方法,减少存储和检索开销;将学习到的知识迁移到新的模态(如音频、视频);确保积累的知识不包含错误或有害信息。
